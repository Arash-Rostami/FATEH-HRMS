# Loading-state pattern — user panel (Dashboard) + admin panel (Filament)

Mandatory, app-wide, four categories for the user-panel Livewire dashboard, plus two admin-panel rules further down. Every "something is happening" moment in the user panel maps to exactly one. No fifth category, no hand-rolled spinner, no per-module invention. Any reviewer (Ollama gate, `claude-reviewer`, `omni-reviewer`, or self-review) checks new/changed loading UI against this table before approving.

| # | Trigger | Component | Notes |
|---|---|---|---|
| 1 | **Load more** — pagination, including scroll-triggered infinite lists | `<x-ui.buttons.load-more action="..." text="..." loading-text="...">` | The `IntersectionObserver` auto-load pattern (`tab/feeds`, `tab/gallery`, `tab/reports` timeline views) is retired in favor of this — same click-based mechanism as every other paginated list (Project/Channel/Contact sidebars, Dms, Authority, Reservation, Ths, Suggestion, ReleaseRequest). One mechanism, one visual, everywhere. |
| 2 | **Navigate to another page, or refresh content in place** (switching sibling pages via `wire:navigate`, OR a filter/tab change re-querying the same page — e.g. Dms's doc-type filter, Faqs' view filter) | `<x-ui.loaders.spin-badge text="...">` | Text adapts to what's actually happening — "در حال جابجایی..." for a page switch, "در حال فیلتر کردن..." / "در حال به‌روزرسانی..." for an in-place refresh. Same component, contextual copy. Already correctly wired into `tab-selector.blade.php`'s route-mode and `messaging/switch-tabs` for page navigation — extend the same component (not a new one) to in-place filter/tab refreshes that previously hand-rolled a CSS ring (Dms's `legend.blade.php`, Faqs' filter panel). |
| 3 | **Initial load of a *standalone* page opened fresh** (hamburger menu / top navbar / left sidebar dock — these all open `target="_blank"`, a genuinely fresh HTTP request, never an in-tab transition) | An adaptive skeleton via `#[Lazy]` + `placeholder()` | The skeleton must be shaped like the actual page — table stripes for Dms/Ths, card grids for Ads/Reservation — composed from the shared primitives below, never one generic block reused everywhere. **See the exclusion rule right below the table — this category does NOT apply to every menu-opened page.** |
| 4 | **Save/action** (submit, endorse, assign, upload, export...) | `<x-ui.buttons.form loading="...">` by default | Escalate to `<x-ui.loaders.bar/>` only when the action is genuinely slow — file uploads, bulk operations, CSV/report export. Most actions (task create/update, message send, ticket assign/close/reply) stay on the lightweight button spinner. |

## `#[Lazy]` policy — all modules, two exclusions (decided 2026-08-24)

`#[Lazy]` trades total time for perceived speed: it never makes a query faster, it just defers the real `mount()`/query to a second request so the first response is a fast, empty skeleton instead of a blank/blocked tab. Final rule: **every module gets `#[Lazy]` + a matching `placeholder()`, except Channel and Contact.** Those two are the only permanent exclusions — real-time chat needs the instant, no-extra-round-trip feel, and enabling Lazy on either measurably broke their test suites (confirmed by differential testing: reverting Lazy fixed the failures). Everything else, including the light-mount modules (Home, Calendar, Energy, Profile) and the in-app tab-switch pairs (Channel↔Contact is excluded anyway; TaskBoard↔Project is Lazy on both sides), is Lazy for consistency — the tiny added round-trip on light modules is an accepted trade for a uniform skeleton experience app-wide.

Confirmed Lazy modules: **Ads, Analytics, Authority, Dms, Energy, Profile (+ its 6 dynamic-component sub-tabs below), Project (+ its 5 dynamic-component sub-tabs — report/analytics/activity/projectCalendar/kanban, `#[Defer]`-attributed as of 2026-08-28, see `app/Livewire/Dashboard/Project/projectPattern.md`), Reservation, Suggestion, TaskBoard, Ths, and the entire `Tab/*` family** (Home, Calendar, Faqs, Feeds, Gallery, Links, Posts, Reports, Status). TeamChat is a deliberate exception — never Lazy/Defer, see the Project doc for why.

### Gotcha: `<livewire:dynamic-component :lazy="...">` needs its OWN `placeholder()` per target class

`Tabs.php` (for the `Tab/*` family) and `ProfilePresenter::tabs()` (for Profile's info/details/skills/about/documents/credentials/onboarding sub-tabs) both mount their swapped-in sub-component via `<livewire:dynamic-component :component="..." :lazy="...">`. Passing `lazy="true"` as a **mount param** is enough to trigger Livewire's Lazy defer mechanism on its own — no `#[Lazy]` class attribute required. But Livewire's placeholder resolution (`Wrapped::__call` in `vendor/livewire/livewire/src/Wrapped.php`) only calls a `placeholder()` method if the **target component class itself** defines one; there is no inherited/shared fallback across dynamic-component swaps. Skip it and Livewire silently falls back to an empty `<div></div>` — the lazy defer still happens, but with *zero visible skeleton*, which reads as "broken" rather than "loading." Every class mounted this way needs its own `public function placeholder(): View { return view('...'); }`, even when `lazy` is set purely via the tabs config array rather than a `#[Lazy]` attribute on the class.

### Gotcha: never place `<x-ui.placeholder/>` inside a `#[Lazy]` module's own view

That component's root carries an unscoped `wire:loading.flex` — it fires on EVERY request of the enclosing component, so any `wire:model.live` flow (energy survey checkboxes, etc.) flashes the full-page skeleton per toggle. The lazy initial load is already covered by the module's own `placeholder()` method (mandatory per the policy above); if a generic spinner is ever needed for a specific action, scope it with `wire:target` like the rest of the app. Removed from `energy.blade.php` 2026-08-31 for exactly this flash, and from the root of `suggestion.blade.php` the same day (it flashed on every `wire:model.live` form interaction there — its departments multi-select also dropped `.live` since nothing server-side depends on the selection until submit). The compliant inverse of that gotcha is `suggestion/placeholder.blade.php`'s in-flight swap (2026-08-31): a `wire:loading`/`wire:loading.remove` pair explicitly scoped to `wire:target="selectSuggestion"` swaps the empty-state panel for the detail skeleton during the click→lazy-mount gap — the zero-blank-moment technique for the gap a `#[Lazy]` submodule cannot cover itself, safe precisely because it is target-scoped.

## Admin panel (Filament) — its own two-rule set

Filament's page lifecycle isn't a Livewire dashboard module, so it doesn't map onto the 4-category table above — but it still must stay visually consistent with it. Two rules, decided 2026-08-24:

| # | Trigger | Component | Notes |
|---|---|---|---|
| A | **Main/global page loader** — every admin page load and Filament-internal navigation | `components/ui/loaders/page-transition.blade.php` | Wired into `app/Providers/FilamentServiceProvider.php`'s `PanelsRenderHook::BODY_END` hook. A `.global-app-loader` fixed, full-viewport overlay (`resources/css/core/filament.css`, blurred backdrop, `pageFadeOut` animation, 400ms delay) wrapping `<x-ui.loaders.spin-badge text="بارگذاری صفحه ...">` — same conic-ring visual as category 2, not a bespoke admin spinner. This is the one and only "main page loader" for the admin panel. |
| B | **Non-Livewire action button** (plain Alpine store + `fetch()`, no `wire:click` at all — e.g. the navbar's cache-reset icon in `filament/resources/dashboard/utilities.blade.php`) | Local Alpine-driven glyph swap: `:class="{ 'animate-spin': $store.x.busy }"` + conditional icon text | **Not** a violation, and **not** convertible to `spin-badge` or `x-ui.buttons.form` — both of those components animate exclusively via Livewire's `wire:loading`/`wire:target`, which never fires for a plain `fetch()` call outside any Livewire request cycle. Forcing `spin-badge` onto a non-Livewire trigger renders a ring that simply never spins. If a button like this is later rewired to go through an actual Livewire method, migrate it to rule A's sibling (category 4, `x-ui.buttons.form`) at that point — until then, the local Alpine boolean is the correct, deliberate exception. |

Do not delete `page-transition.blade.php` or its render hook when doing dashboard-scoped loader cleanup — grep for `view('components.ui.loaders...` (PHP-side, not just Blade `x-ui.loaders.*` usages) before retiring any shared loader component, since a PHP `view()` call like this one won't show up in a `x-ui.loaders.*` Blade grep. This exact miss caused a full admin-panel outage on 2026-08-24 (spinner.blade.php deleted, FilamentServiceProvider's `view('components.ui.loaders.spinner')` call left dangling) — recovered by restoring the file from git history, then migrating the one real consumer to `page-transition.blade.php` and re-deleting it properly.

## Retired (do not reintroduce)

- `components/ui/loaders/spinner.blade.php` — deleted 2026-08-24, briefly restored the same day after breaking the admin panel (see above — a PHP-side `view()` consumer was missed on first deletion), then permanently retired once `page-transition.blade.php` replaced its one remaining real use. Was the bare route-aware conic ring with no label. Its Blade-side consumers (`suggestion.blade.php`'s detail-panel fallback, `tab/posts/details.blade.php`'s slideover fallback, `suggestion/list.blade.php`'s search-loading state) were converted to `spin-badge`; its PHP-side admin consumer (`FilamentServiceProvider.php`) was migrated to `page-transition.blade.php`. Superseded by `spin-badge` (same visual, always paired with context text) for category 2, and by per-module skeletons for category 3.
- The hand-rolled `border-b-2 animate-spin rounded-full` CSS ring (formerly duplicated independently in `dms/legend.blade.php` and `tab/faqs.blade.php`) — superseded by `spin-badge` (category 2).
- Bare Material Symbols `progress_activity` + `animate-spin` hand-rolled inline on buttons (Channel/Contact/Profile/Energy/Suggestion) — superseded by `<x-ui.buttons.form loading="">`'s built-in spinner (category 4).
- `wire:loading.attr="disabled"` with no visual spinner (TaskBoard, Ths) and `wire:loading.class` dimming with no spinner (TaskBoard's column) — both get a real spinner via category 4, dimming/disabling can stay as a *supplement*, never the only cue.

## Shared skeleton primitives (`components/ui/loaders/skeleton/`)

Composed per module, not copy-pasted per module. Each takes only sizing/count props — no page-specific logic.

- `bar` — a single shimmering rounded rectangle, `width`/`height` props. The atom everything else is built from.
- `avatar-row` — a circle + one or two bars, for a list row with an identity (sidebar rows, people cards).
- `card` — a rounded rectangle with an optional inset bar-stack, for grid tiles.
- `table-stripe` — a header bar + N body rows.
- `column-stack` — a vertical stack of `card`s inside a bordered column, for kanban.
