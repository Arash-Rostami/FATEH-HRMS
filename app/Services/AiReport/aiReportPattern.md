# AI Report — AI-generated management report (engine + behaviour)

Governing doc for `app/Services/AiReport/`, `GenerateReportJob`, the `AiReport` model and its admin resource. UI structure and Livewire gotchas live in `app/Livewire/Dashboard/AiReport/reportPattern.md`.

A user writes a request (and may attach files). A queued job asks an AI model to turn it into a structured management report. The answer is validated, stored, and rendered as a clean A4-ready document that can be refined, shared and printed.

## The flow

1. **Compose** — the user types a prompt (length limits in `config/ai/report.php` `prompt`) and optionally attaches PDF, image, Word, Excel, CSV, MD or TXT files. File count, allowed types and every upload SIZE (per file, per inline PDF/image, all inline files together, grand total) live in `ai.report.upload.{max_files,mimes,accept,per_file_kb,inline_kb,inline_total_kb,total_kb}` and sizes are read directly from `config('ai.report.upload.*')`, the master source (no tier fallback, no `file_upload_limits.php` involvement).
2. **Generate** — `GenerateReportAction` takes a per-user lock, checks the user has no run in progress and has daily quota left, creates the row as `generating`, consumes one quota unit, and dispatches `GenerateReportJob` (payload is the report id plus a run token). A failed run still records the tokens it spent (`ReportAiService::$spent`). Text/CSV uploads in UTF-16 (BOM) or Windows-1256 are transcoded before being skipped as corrupt, and `BlockCatalog::retotal` keeps the column's own separators.
3. **Extract** — `FileExtractor` turns attachments into text (Word, Excel, CSV, MD, TXT) or inline parts (PDF, images). It enforces size, zip-bomb and encryption limits, and reports skipped files with a reason.
4. **Ask** — `ReportAiService` (prompt, schema and repair loop; the HTTP call is delegated to `App\Services\Ai\AiClient`) sends one chat request to the OpenAI-compatible gateway with a strict JSON schema and a system prompt. Attached text is fenced as untrusted data. The user message is an array of parts: inline media (PDF as `file`, jpeg/png/webp as `image_url`) FIRST and ONE text part LAST, so the closing `FINAL REMINDER:` line of the text part is the last thing the model reads before answering (and in block mode the text also carries `CURRENT_BLOCK` plus a read-only `REPORT CONTEXT` line: report title and up to 16 section headings of 80 chars, "never output it, never change other sections"). At most 2 provider calls per run (one retry for an empty answer, or one repair call for an invalid one).
5. **Validate** — `AiClient::parseJson()` (static, shared with the other AI features) first tolerates a sloppy reply: strict `json_decode`; if that fails or yields a scalar/list it takes the substring from the first `{` to the last `}` (so markdown fences or prose around the object are stripped); anything still not an object throws a `JsonException`, which feeds the repair call. `BlockCatalog::validate()` then checks the answer against the block catalog, cleans every string (no HTML, no bidi override controls) and flags tables whose totals or percent column do not match the rows (`check` = `mismatch`, computed by `mismatchColumns()`, which returns the offending column indexes; totals are NOT recomputed at generation time). Invalid output throws and triggers the single repair call.
6. **Store** — the job writes spec, title, model and token count, marks the row `ready`, and deletes the temporary upload folder. Any failure goes through `AiReport::markFailed`, which maps to a closed set of fail codes and refunds the quota exactly once (except user-caused codes listed in `no_refund`).
7. **Render** — Blade components draw the spec: title, KPI tiles, summary, table, callout, section.

## Report content (the block spec)

A report is `lang` (`fa` or `en`), a `title`, and `pages[].blocks[]`. Block types:

| Type | Holds |
|---|---|
| `title` | heading, subtitle |
| `kpi_row` / `facts` | `kpi_row`: `kpi_min`–`kpi_items` tiles (2–4); `facts`: 1–`facts_items` tiles (1–8); each tile label, value, hint, tone |
| `summary` | heading, bullets, highlight |
| `table` | heading, columns (MORE than `spec.columns` is rejected, never silently cut), rows (cut at `spec.rows`), optional total row (a total that is entirely blank or "—" is dropped), optional percent column, optional status column, footnote; carries `check` = `mismatch` when a numeric column's sum differs from its total or a percent column does not add to ~100 |
| `action_items` | localized fixed columns (owner/action/due/status), rows, status column |
| `progress` | localized fixed columns (item/target/actual/progress), rows, server-computed percent column |
| `chart` | kind (bar/pie), labels, series (name + plain values), heading, unit |
| `section` | heading, paragraphs, bullets |
| `callout` | variant (info/warning/decision), heading, paragraphs, lettered options, risk |

Caps (all `config('ai.report.spec.*')`): `pages` 6, `blocks` 8 per page (`one_page_blocks` 6 for a one-page LENGTH), `columns` 6, `rows` 40, `items` 12 per list, `options` 5, chart `chart_labels` 12 / `chart_series` 3 / `pie_slices` 6, string lengths `short` 200 / `cell` 120 / `paragraph` 1200, whole spec `bytes` 65536.

Persian reports use Jalali dates and Persian digits. Unknown figures are written as a dash, never invented. `BlockCatalog::validate()` guarantees an assumptions `section` (the localized config heading) exists: when the reply has none it appends the config fallback section before a trailing callout (or at the end; on a new page when the last page is full) — which is also why even a ONE-block block-mode reply comes back with a second, fallback assumptions section. Its exact heading is pinned on every write path — block refine, manual block edit, rename and revert all preserve it.

## What users can do

- **Refine** in chat — each request creates a new version (the last N are kept; the original prompt is labelled when older ones were trimmed). Refining uses the current report as context.
- **Refine one block** — the per-block button sets `form.block` (`p:b`); the job then sends ONLY that block as `CURRENT_BLOCK` with a block-mode system prompt (no `REPORT TYPE:`/`LENGTH:` lines, audience kept, parent `lang` forced onto the reply), and `GenerateReportJob::mergeBlock()` splices back the first reply block whose type matches the original, skipping an inserted assumptions section (type mismatch = `invalid_spec` with a refund; an assumptions section keeps its exact heading; a title block also updates spec title and row title; presets untouched). Costs one quota unit like a full refine; on a shared report it forks identically to a full refine; retry restores the same block target.
- **Manually edit one block** — the pencil button opens the block editor (`blockRef` + `blockDraft`); `UpdateReportAction` re-authorizes under the lock (`canRevert`: owner + ready + unshared), forces the type from the stored block, re-derives table totals (`retotal`) before normalizing, validates the WHOLE spec, and pushes a version marked `manual` with the label suffix « · دستی». No quota. `retotal` rewrites only a column whose stored total matched the stored rows' sum (a real total); an average or rate total stays exactly as typed and keeps its `check` mismatch flag — percent and status columns never satisfy the gate, so they need no special case. Precisely, per column `j`, `retotal($draft, $original)` SKIPS it when: the draft's total cell differs from the stored one (the user typed a total — it wins), the stored total contains any letter (a unit such as «تومان»), any stored row cell is non-numeric or contains a letter (a unit column), or the stored total did not equal the stored rows' sum within `max(1, |total| * check.total_tolerance)` (not a real sum to begin with); otherwise the total becomes `round(sum(draft rows), 2)`, rendered with Persian digits when that column's rows use them. `BlockCatalog::mismatchColumns($block)` is the shared helper that lists the offending column indexes (a numeric column needs at least `max(2, numeric_ratio * rows)` numeric cells to be judged; a percent column must add to ~100 within `percent_tolerance`); `checkTable()` sets the flag from it and `Main::editBlock(ref, flagged)` uses it to word the pre-filled refine request. A title-block edit writes the heading, the spec `title` and the row `title` together, both through the local `$spec` copy (never an indirect model-attribute write). Read-only fields: the assumptions heading (disabled, and restored server-side even if tampered), no row add/remove (the editor only edits existing cells).
- **Retry** a failed run (files must be attached again: if the failed version had files, retry only restores the prompt and expands the composer). A retry is a normal refine, so it costs ONE quota unit (the failed attempt's unit was refunded). Hidden for user-caused failures (`no_refund`: `too_large`, `blocked`) — the failed card tells the user to rewrite the request instead, and the quota is not returned; every refundable failure shows the button, a "this retry consumes one unit" note, and a per-cause hint under the reason line.
- **Rename**, **save** (drafts are stale after a configured number of days), **revert** to an earlier version. Rename, revert and manual edit need the report ACTIVE and UNSHARED (`canRename`/`canRevert`); refine needs it active; share needs it active and ready. An inactive report can only be re-activated, viewed or deleted by its owner.
- **Share** with chosen colleagues. Sharing replaces the recipient list, notifies recipients, and gives a signed link valid for a configured number of days. A shared report is frozen: refining it creates a new private copy. An inactive report cannot be shared (button hidden; the action re-authorizes).
- **Copy** the report as plain text, or **print** it (A4, one page per report page, dark theme restored afterwards). The print header (owner · Jalali date, first printed page only) comes from the dispatcher's `author` prop; the inline `@page @bottom-center` rule (rendered with the document itself) numbers every page in Chromium ≥131 (Firefox/Safari print without them — accepted; Latin digits — accepted). There is ONE print button; PDF is the browser print dialog with «ذخیره به‌صورت PDF» as destination (the old separate PDF button was removed).

## Prompt contract (`config('ai.report.rules')`, the system prompt, + per-request lines)

- Placeholders `{blocks}`, `{one_page_blocks}`, `{columns}`, `{kpi}`, `{kpi_min}`, `{facts}`, `{chart_labels}`, `{chart_series}`, `{pie_slices}`, `{assume_fa}`, `{assume_en}` are substituted with `strtr` from `config('ai.report.spec.*')` / `assumptions.heading` — in the system prompt (`ReportAiService` reads it from `ai.report.rules`; it is no longer a class constant) AND in the `rules` text of the chosen type, length and audience (`REPORT TYPE:`, `LENGTH:`, `AUDIENCE:` lines), so a number in the rule text is never hard-coded: edit the config cap and every prompt follows.
- Rule intent worth not breaking: **0** output shape (one JSON object, parts live in `pages[i].blocks[]` with a `type` key, never top-level keys, no fences or text around it, always a non-empty top-level `title`, extra pages only when LENGTH asks); **3** every block has ALL keys (null when not applicable), the per-type required fields, and a total equals the sum only for additive columns (averages, rates, variance percentages get "—"); **4** units stay in cell text, `percent_column` only for a share-of-total column, `status_column`, at most `{columns}` columns (wider data is split into two tables, because `BlockCatalog` rejects instead of truncating); **6** never invent, estimate or round figures, unknown → "—" and the gap named in the assumptions section, `SYSTEM NOTES` honoured; **9** relative periods are Jalali and resolved against the "Today in Asia/Tehran" line of the user message, a missing period defaults per REPORT TYPE and is declared in the assumptions, a too-vague request yields a minimal all-"—" report; **11** precedence — output shape, field rules and rule 10 win (except in BLOCK MODE), REPORT TYPE/LENGTH/AUDIENCE override the default structure, the USER REQUEST decides only content, language and focus.
- Block mode (`options['block']`) drops the `REPORT TYPE:` and `LENGTH:` lines and appends `BLOCK MODE:` (exactly one block, same type, full keys, no assumptions section, no title); the AUDIENCE line stays. `GenerateReportJob::mergeBlock()` splices back the FIRST reply block whose `type` equals the original's, skipping an assumptions `section` unless the original itself is that section (decode appended a fallback assumptions section even to the one-block reply, so block 0 of the reply is not always the revised one); none found → `invalid_spec`.

## Notifications

Sharing is the only event that notifies. Recipients get an in-app bell notification ("a report in Smart Report Builder was shared with you") with a View button that opens the report through the signed link. A menu dot next to «گزارش ساز هوشمند» also lights until the recipient opens the report (`seen_by`, `UnseenAiReports` indicator); the bell clears when closed. There is no notification when the page is closed during generation; while the page is open, a toast announces the finish of a run the user is not currently looking at (`Main::announceFinished`). Its explanation lives in the badge legend (`BadgeLegendCatalog`, entry `ai-report-controller`, group compliance) and is shown beside the user legend.

## Limits and safety

- **Daily quota** per user (cache counter, key per user per day, cap `config('ai.report.daily_cap')`, trait `HasDailyQuota`, key `ai-report:quota:{uid}:{Y-m-d}`). One unit is charged by each generate, refine (whole report or one block) and retry; manual edit, revert, share, print and copy are free. Charged once at start, refunded at most once on infrastructure failures (not for `too_large` / `blocked`); the refund lands on the day recorded in the version's `quota_day`.
- **Stale runs** — a run stuck in `generating` past the configured minutes is failed and refunded the next time a list or report loads.
- **Tmp sweep** — the app-wide `storage:prune-tmp` (daily 04:35, config `filesystems.tmp_prune`) removes `ai-report/tmp/{id}` folders and Livewire temp uploads whose newest file is older than 24 hours (age-only, allowlisted roots, never follows symlinks); normal runs clean up themselves.
- **Why AI Report has its own temp folder** — every other module's uploads go straight from Livewire's shared `livewire-tmp` inbox to their final home at save time; AI Report is the only module whose files must outlive the request (the worker reads them minutes later while it talks to the provider), so `GenerateReportAction` copies them out of the inbox into `ai-report/tmp/{id}` and deletes the inbox copy immediately. That private waiting room is the sole reason this module has an entry in `tmp_prune.roots`; if a future module ever needs the same request-outliving staging, it adds one `['disk', 'path']` line of its own.
- **Authorization** — every action goes through `AiReportAccessPolicy`; read-only viewers (recipients, admins) cannot change anything.
- **Secrets** — the gateway address and key live only in `.env` and are never logged, thrown or shown.
- **Attachments** are deleted after generation; their content is not stored.

## Shared AI layer and the `<module>:ai` convention

- `App\Services\Ai\AiClient` owns the gateway call for every AI feature: `isConfigured()`, `json(messages, schema, feature)` returning `['content' => ?string, 'tokens' => int]` (errors `unreachable`, `too_large`, `blocked` as `DomainException`; an HTTP 4xx/5xx surfaces as `Illuminate\Http\Client\RequestException`, not mapped by the client, so callers that must degrade gracefully catch it, as `SuggestTicketTextAction` does), `lastTokens()` (token total of the last call, set before any throw so a cut-off or filtered reply is still counted; 0 on a connection failure; a 200 body that is not a JSON object is treated as an empty reply, i.e. the repair/`empty` path), static `parseJson()` and `setting(feature, key)` = `config("ai.{feature}.{key}") ?? config("ai.gateway.{key}")` for `timeout`/`connect_timeout`/`max_output`, FAILING LOUD: when neither key exists it throws a `RuntimeException` naming both keys and telling to run `php artisan config:clear` (a stale config cache would otherwise silently yield a 0 timeout); key and url always come from the gateway, and so does `model` unless the feature config sets its own (`config/ai/correspondence.php` `model` from env `AI_CORRESPONDENCE_MODEL`; `null` falls back to the gateway), so call `AiClient::setting($feature, 'model')` wherever the model is recorded. `GenerateReportJob` sizes its timeout from `AiClient::setting('report', ...)`.
- A new AI feature inside an existing module is a `<module>:ai` VIEW, not a new module: add `ai` as the LAST entry of the module's `views` in `config/modules.php` (the first view stays the default and can never be hidden), gate every surface with `tenantOff('<module>:ai')` (`tenantOff('<module>')` also hides it), put ALL its settings in its own file `config/ai/<module>.php` (loaded as `ai.<module>`; see "AI config layout" below), give the model `HasDailyQuota` with its own `quotaFeature()` (key `ai-{feature}:quota:{uid}:{Y-m-d}`, cap `ai.{feature}.daily_cap`) and add `aiView: '<module>:ai'` to the module's `BASE_ITEMS` entry in `menu.js`. `ths:ai` is the first one (`app/Livewire/Dashboard/Ths/thsPattern.md`); `ai-report` and `ai-assistant` stay whole modules.
- **AI config layout and the rule for future modules.** `config/ai.php` holds the SHARED gateway only (`gateway`: `key`/`url` from env `AI_REPORT_API_KEY`/`AI_REPORT_API_URL`, `model` from env `AI_REPORT_MODEL` with fallback `Gemini-3-Flash-Preview`, `timeout`, `connect_timeout`, `max_output`) and must not define module keys. Each AI module owns exactly ONE file `config/ai/<module>.php` with every setting of that module and nothing elsewhere: `config/ai/report.php` (`daily_cap`, `timeout`, `connect_timeout`, `max_output`, the `rules` system prompt, types/lengths/audiences, `prompt`, `upload`, `extract`, `spec`, `provider`, `job`, `lock`, stale/share/version limits, `no_refund`), `config/ai/correspondence.php` (the `correspondence:ai` view: `daily_cap`, `model`, `timeout`, `connect_timeout`, `max_output`, the Smart-mode `prompt` texts, fonts, types, upload and lock limits) and `config/ai/ticket.php` (`daily_cap`, `timeout`, `connect_timeout`, `max_output`, `down_for`, `cooldown`, `input_max`, `no_refund`, `subject_max`, `description_max`, `rules`, `skeleton`). Laravel loads the folder file as `ai.<module>` merged under `ai`. Tenant on/off stays in `tenants.php` via the `<module>:ai` view and the module registry in `modules.php`. `config/ai_report.php` and the `ai` group of `file_upload_limits.php` no longer exist.
- Deploy: after the release that introduced `config/ai.php` and `config/ai/`, run `php artisan config:clear` (and re-cache where cached); delete the old `config/ai_report.php` on the server.

## Admin

A read-only Filament resource (`AiReportResource`) reached from the Reports resource through switch buttons. Admins can view, toggle `active`, and delete (not while a report is generating).
