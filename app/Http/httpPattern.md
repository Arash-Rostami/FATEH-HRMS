# HTTP Middleware Layer — app/Http/Middleware

Five middlewares (`UpdateLastSeen`, `EnsureHasPermission`, `EnsureUserModulePermission`, `EnsureTenantModuleOn`, `SecureLetterLink`), each one behavioral rule (§2 documents the inactive-user gate that spans them, §6 is the public-letter-link stack). (Controllers live in `app/Http/Controllers/`: single-action JSON endpoints — `ToggleCalendarController`, `IconMissController` (`POST /icon-miss`, public icon-font miss report: string-only name, once-a-day log line, `icon-miss` limiter = 20/min per IP + 60/min global; see `resources/icons/iconsPattern.md`; test `IconMissTest.php`) and `ProjectPulseController`, the latter documented in `app/Livewire/Dashboard/Project/projectPattern.md` "Performance pass 2026-08-28"; tests: `tests/Feature/Http/ProjectPulseControllerTest.php` and `tests/Feature/Http/ToggleCalendarControllerTest.php`, one dedicated file per controller.)

## 1. `UpdateLastSeen` — presence throttle + inactive-session boot (2026-10-02)

- Registered twice: `bootstrap/app.php` `appendToGroup('web', ...)` (user panel) and the admin panel's `->middleware([...])` in `AdminPanelProvider` — so it runs for **both panels**.
- Two jobs, in order:
  1. **Inactive boot.** If the authenticated user's `status` is not `active` (`User::isActive()`, single source), log out the `web` guard and redirect to `/login`. This seals sessions that were created *before* an admin deactivated the user — a logged-in user is booted on their very next request, in either panel.
  2. **last_seen throttle.** Otherwise `touchLastSeen()` at most once per `User::TOUCH_MINUTES` (3), keyed `last_seen:{id}` in cache. All "online" derivation reads `last_seen` through ONE window, `User::ONLINE_MINUTES` (10) — `isOnline()`, `scopeOnline()`, the Contacts "online" filter, Home's team pulse, the admin Users stats and HR analytics all use `User::onlineSince()` (2026-10-14; before this it was 5 min in the user panel and 15 min in admin/HR) — never a boolean column. The touch interval stays well under the window (3 vs 10) so an active user can never flicker offline. `User::markOffline()` (Logout listener) backdates `last_seen` to `ONLINE_MINUTES + 1` minutes, so sign-out is instant under any window value.
- Guard nuance: it logs out `Auth::guard('web')` because both panels' guards resolve to `web` (Filament default guard); do not switch to `$request->user()->logout()`-style calls here.

## 2. The inactive-user gate — three seals, one source (2026-10-02)

A user with `status` other than `active` cannot hold a session anywhere. Enforced at three independent points so no path slips through:

1. **User-panel login** — after a successful login `Login::destination()` returns the remembered `url.intended` (a guest GET to any protected page stores it) EXCEPT when its path is exactly the Launchpad page `/launchpad` (2026-11-26: staff were landing on Launchpad after login because that address was the remembered one; the SSO entry `/launchpad/{id}/go` and the file routes are NOT excluded, a sibling app sends the user there to sign in and must get back to it); in that case, and when nothing is remembered, it is `config('fortify.home')` (`/dashboard`). `App\Livewire\Auth\Login` delegates to one Action per method in `app/Livewire/Auth/Actions/` (`PasswordLoginAction`; the SMS-code pair `SendLoginCodeAction`/`VerifyLoginCodeAction`, available only while `notify:sms` is on and the provider is configured). `PasswordLoginAction` logs in through `Auth::attemptWhen` with an active-user check (never logs in then out, keeps the guard's timing protection) and returns an error string or `null`; `SendLoginCodeAction` returns an error string or `null`; `VerifyLoginCodeAction` returns the `User` or `null` and the component then calls `Auth::login()`. Errors land on `email`/`phone`/`code`. The «ورود با پیامک» switch beside «مرا به خاطر بسپار» (`smsLogin`) swaps email+password for phone+code at the SAME card height (never add a row to one mode only): the code field is always rendered (disabled until a code is sent) and the forgot-password chip goes `invisible`, not removed. The footer row (remember-me, SMS switch, forgot/resend chip) is `flex-nowrap`, one row on every width. A sent code locks resend for `SendLoginCodeAction::COOLDOWN` (60 s, same as the server limiter): `Login::sendCode()` dispatches `login-code-sent` and the resend is a tonal `<x-ui.buttons.form>` in the forgot-password chip's slot (same size `!h-8 !px-3 rounded-lg text-xs font-bold`), disabled while locked and reading «ارسال مجدد N ثانیه» (text + live Persian number), then the refresh icon + «ارسال مجدد»; driven by the `authResend` factory (defined and registered in `resources/js/auth.js`, auth bundle only; `x-data` on the `<form>`). Owner choices: text + number, and the footer slot (the in-field versions were tried and rejected). Limits per number: 1 code per 60 s, 5 per hour, 10 per day (the hour and day counters move only after a successful send; the cooldown is released after a failed send), 5 wrong tries per code (counted BEFORE comparing); per IP 60 sends per hour and 60 verifies per 10 minutes. The submit button reads `$outcome` (`success`/`fail`, green check / red cross): success does NOT `redirect()` (Livewire skips the re-render on a server redirect, the check would never paint) — it sets `outcome` and leaves via `$this->js()` after 800ms to the `url.intended` session value.
2. **Admin-panel login** — `App\Filament\Pages\Auth\Login` (subclass of the vendor page, registered via `->login()` in `AdminPanelProvider`) overrides `authenticate()`, calls the parent, then re-checks `Filament::auth()->user()->isActive()` and logs out + throws `ValidationException` on key `data.email` (the vendor page's own error key).
3. **Every live request** — `UpdateLastSeen`'s boot above.

Tests: `tests/Feature/Auth/LoginTest.php` (user panel), `tests/Feature/Filament/AdminLoginTest.php` (admin panel). `UserFactory` defaults `status => 'active'` deterministically — a random default silently made any login-asserting test flaky once this gate existed; tests that need an inactive user pin it.

## 3. `EnsureHasPermission` — admin-panel route gate

Role-first permission model with developer bypass. Full model: `app/Providers/Filament/adminPanelPermissionLogicPattern.md`.

## 4. `EnsureUserModulePermission` — alias `module:{name}` (user panel)

Per-module view gate on user-panel routes (`bootstrap/app.php` alias): guests → login, developers → always pass, everyone else needs a `Permission::forUser()` row with `can($module, 'view')`, else 403. This is the user-panel counterpart of the admin panel's `EnsureHasPermission`.

## 5. `EnsureTenantModuleOn` — alias `tenant.on:{key}` (2026-11-02)

Per-company switch gate: `abort_if(tenantOff($key), 404)`, so a route can be turned off per tenant in `config/tenants.php` `modules` without an `if` in the routes file. First user: `Route::middleware(['guest', 'tenant.on:password-reset'])` around the forgot/reset pages (Fateh off, Persol on; full list of what the switch touches in `config/tenantPattern.md`). The key is read at request time, so it works with a cached route table. Test: `tests/Feature/Http/HttpRoutesTest.php`.

## 6. `SecureLetterLink` — alias `letter.link`, the public letter-link stack (2026-11-09)

The only unauthenticated, non-JSON controllers: `CorrespondenceLinkController` (`GET /c/{id}-{token}` → `correspondence.link`, `/pdf` → `correspondence.link.pdf`, an outside recipient's private view/PDF of an approved letter) and, for contrast, the authenticated `CorrespondencePdfController` (`GET /correspondence/{id}/pdf` → `correspondence.pdf`, in the `auth` group, `canView`, `private, no-store`) and `CorrespondenceAttachmentController` (`GET /correspondence/{id}/attachment/{index}` → `correspondence.attachment`, same `auth` group, delegates to `DownloadAttachmentAction`: `canView`, path under `correspondence/{id}/`, file must exist, 404 on any miss; PDF inline, other types download). The link routes sit in ONE group in `routes/web.php`: middleware `letter.link` + `throttle:letter-link` (`RateLimiter::for('letter-link')` in `FortifyServiceProvider`: 20/min per IP + 120/min global), `withoutMiddleware` of `EncryptCookies`, `AddQueuedCookiesToResponse`, `StartSession`, `ShareErrorsFromSession`, `ValidateCsrfToken` and `UpdateLastSeen` (no session, no cookies, no CSRF, no presence touch), and route constraints `id = [1-9][0-9]{0,9}`, `token = [A-Za-z0-9_-]{43}`. `SecureLetterLink` stamps `SecureLetterLink::HEADERS` on every response (`X-Robots-Tag: noindex, nofollow`, `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, `nosniff`, `X-Frame-Options: DENY`, `frame-ancestors 'none'`); the controller reuses the same constant for downloads, and the `bootstrap/app.php` renderer turns any 404/429 under `c/*` into an empty body with those headers. Rules: identical empty 404 for every miss (missing, wrong token, revoked, expired, unapproved, confidential); only the sha256 of the token is stored (`parties[].token_hash` / `token_hash_next`, `hash_equals`); a GET records the open under a row lock through `SendCorrespondenceJob::writeQuiet`, HEAD never does; the tenant switch is NOT checked here (links already sent keep working). `TRUSTED_PROXIES` must be set or the per-IP limiter sees the proxy. Full contract: `app/Livewire/Dashboard/Correspondence/correspondencePattern.md` §12.

## 7. File protection grades — pick one per module, no fourth pattern (2026-11-10)

Every stored file belongs to exactly one of three grades. A new module chooses one; do not invent another mechanism (no per-module signed routes, caches or ad-hoc rewrites).

1. **OPEN** — public disk via `StoresAttachedFiles`/`storeAttachment` + `FileNamer::stored`; reachable by the direct `/storage/<folder>/…` URL. For content meant for everyone: avatars, feed, gallery, link icons, onboarding, letterheads, post images.
2. **PRIVATE BY APACHE** — same public-disk storing code, PLUS an authorized route (permission lookup, then serve; the `Dms\Main::getAuthorizedFile`/`serveFile` shape), PLUS one Apache rewrite line in `public/.htaccess` redirecting `/storage/<folder>/` to that route, inserted idempotently by `scripts/setup-container.sh` and checked by `scripts/verify-health.sh`. Admin/developer are served via `hasElevatedRole()`. Examples: DMS (the session-cookie shape); Launchpad (2026-11-17, the path-token variant — the authorized route sits OUTSIDE auth and takes an HMAC path token `{uid}-{exp}-{sig}` instead of a login cookie, because the program opens in a sandboxed iframe (`sandbox="allow-scripts"`) that sends no cookie on its CSS/JS sub-requests, and a relative sub-request URL cannot carry a signed query string — the token rides the PATH, which every sub-request inherits from the iframe `src` base; never `temporaryUrl()`). Guarded folders today: `dms`, `launchpad`. When adopting, add the folder name to the scripts' guarded list.
3. **PRIVATE EXCLUSIVE BY APP** — private `local` disk, no public URL at all. Pictures embedded in a page get a short-lived Laravel signed `temporaryUrl` from ONE helper (Correspondence `privateSrc`); files the user clicks go through a permission-checked route/controller (Correspondence attachment + PDF). Example: Correspondence. Grade 3 does not use `StoresAttachedFiles`/`CleansAttachedFiles` (both are hard-wired to the public disk): the module owns its writers and deleters on `Storage::disk('local')` (Correspondence `LetterUploads`, `LetterSeal`, `LetterBody`), names files with `FileNamer::stored`, and serves them only via `DownloadAttachmentAction` / `privateSrc`.

| | 1 Open | 2 Private by Apache | 3 Private exclusive by app |
|---|---|---|---|
| Who may see it | anyone with the URL | users the route permits (+ admin/developer) | users the app permits (staff by login, outsider by secret link) |
| Where stored | public disk | public disk | private `local` disk |
| How served | direct `/storage/…` | authorized route; direct URL redirected by Apache | embedded: signed `temporaryUrl`; clicked: permission-checked controller |
| What protects it | nothing (by design) | route check + `.htaccess` rewrite | no public path; signature stamp + route check |
| On rebuild/deploy | nothing | rewrite line must survive: `setup-container.sh` re-inserts it, `verify-health.sh` checks it; never upload `public/.htaccess` blindly | keep `local` disk `serve => true`; nothing else |
| Choose when | content is public by nature | files must be private but existing public-disk code/links stay | confidentiality matters more than reuse (letters) |

Where things sit today (as far as the code shows): DMS = 2; Launchpad = 2 (path-token variant, `launchpad/files/...`); Correspondence = 3; avatars, feed, gallery, link icons, onboarding, letterheads, post images = 1. Media (2026-11-21) is grade 1 on the public disk (`media/files`, `media/covers`, plus transcript/chapter paths); writes and deletes go through `CleansAttachedFiles` in `HasMediaHooks`, never a raw `Storage::delete`. Business folders `task/attachments`, `ticket/*`, `release_request/attachments`, `reports/files`, suggestions, `profiles/docs`, resources are currently grade 1 (unguarded) and are candidates for grade 2 later. Related: `app/Livewire/livewirePattern.md` (upload/disk rules, DMS section), `app/Support/supportPattern.md` §5, `app/Livewire/Dashboard/Launchpad/launchpadPattern.md`, `temp/winterra/paas-setup.md` §5.

## 8. `LaunchpadGoController` SSO handoff page (2026-11-19)

`GET /launchpad/{launchpad}/go` answers an SSO sibling with a standalone page (`livewire.dashboard.launchpad.go`) that carries the signed assertion in a hidden form field, so the response is locked down: `Cache-Control: no-store`, `Referrer-Policy: strict-origin` (not `no-referrer`, which would send `Origin: null` to the receiver), `X-Content-Type-Options: nosniff` and `Content-Security-Policy: default-src 'none'; style-src 'self'; font-src 'self'; form-action {receiver origin}; base-uri 'none'; frame-ancestors 'self'` (no scripts at all; `<meta http-equiv="refresh" content="50">` re-mints it while the page waits). The route stays in the auth group with `throttle:30,1`; every failed check is the same empty 404. The page is framed only by Fateh itself (the pinned pane); the sibling must allow Fateh as a frame ancestor on ITS pages. Fateh sends no global `X-Frame-Options` from app code; confirm the server config does not either. Details: `launchpadPattern.md` §7.

## 9. Media progress and notes (2026-11-21)

`MediaProgressController` and `MediaNoteController` are invokable and share `GuardsJsonEndpoint`: no user is JSON `401`, a missing or mismatched `_token` is JSON `419`, a malformed body is JSON `422`. Success is `204` (progress, and note delete) or `201` `{id, position, body}` (note add). Never a redirect. Both POST routes (`media.progress`, `media.notes`) sit in `routes/web.php` OUTSIDE the `auth` group (otherwise an unauthenticated beacon would get a login redirect instead of the JSON `401`) with `throttle:media-progress` (120/min per user + 600/min per IP) and `throttle:media-notes` (30/min per user + 300/min per IP), defined in `FortifyServiceProvider::boot()`. They are excluded from the framework CSRF middleware in `bootstrap/app.php` (`validateCsrfTokens(except: ['media/progress', 'media/notes'])`), because `navigator.sendBeacon()` cannot set the `X-CSRF-TOKEN` header: the controllers read `_token` from the body themselves and answer the JSON `419`. The page is `GET /knowledge` (route `knowledge`, the Livewire shell `Knowledge\Main`) inside the `auth` group; `GET /media[?open=&t=]` is an UNNAMED 302 to `/knowledge?tab=media` (unnamed so it never re-claims a tenant slot) and the two POST routes carry `tenant.on:knowledge:media`, because the route-name guard only covers the whole `knowledge` module, not its `media` view.

## 10. Push subscription endpoint (2026-11-23)

`PushSubscriptionController` (invokable, `GuardsJsonEndpoint`: JSON `401`/`419`/`422`, success `204`) sits INSIDE the `auth` group as `push.subscription` (`POST /push/subscription`, `throttle:20,1`), unlike §9: it needs a real session, and the body must carry `_token` as well as the CSRF header. It validates `endpoint` (https, no userinfo, port 443 or none, host exactly `fcm.googleapis.com` or a strict suffix `.push.services.mozilla.com` / `.notify.windows.com` / `.push.apple.com`, characters `[a-z0-9.-]` only — the server later POSTs to this URL, so this is the SSRF guard), `keys.p256dh` (base64url, 65 bytes starting `0x04`), `keys.auth` (base64url, 16 bytes) and the two scope booleans. Both scopes false deletes the row; an endpoint owned by ANOTHER account can be taken over or deleted only with the same `p256dh`/`auth` keys (`PushSubscription::keysMatch`), so an endpoint string alone is never authority; `sync` locks the user row and retries deadlocks. See `resources/js/scriptPattern.md` §9 "Web Push layer".

## 11. Public `/offline` page (2026-11-23)

`GET /offline` (route `offline`, view `errors/offline.blade.php`) is the page the service worker serves when a navigation fails for lack of network. It sits OUTSIDE the session stack on purpose, with the same `withoutMiddleware` list as the launchpad-file route (cookies, `StartSession`, `ShareErrorsFromSession`, CSRF, `UpdateLastSeen`), answers `Cache-Control: public, max-age=3600` and needs no login, so a cached copy is identical for everyone. The view uses inline CSS and system colours only (no `@vite`, no JS, no hashed asset) because the app's tokens and bundles are not available offline. See `resources/js/scriptPattern.md` §4.1.
