# AI Report Module Pattern Guide

Prompt (+ optional files) to a structured, printable report (`/ai-report`). One queued job calls an OpenAI-compatible gateway, the result is a validated JSON spec rendered by Blade block components. Owner-private by default; explicit save and replace-style share to colleagues. Livewire v4, Filament v5 (read-only admin), Laravel 12, PHP 8.2. General rules live in `app/Livewire/livewirePattern.md`; what the module does end to end is in `app/Services/AiReport/aiReportPattern.md`; this doc holds only what is specific to the UI/Livewire side and the non-obvious rules.

Routes (inside the `auth` group): `GET /ai-report` (`ai-report`) and `GET /ai-report/shared/{report}` (`ai-report.shared`, `signed`). `mount` redirects the signed URL to `/ai-report?r={id}` after `canView`, so the signed link is only an entry ticket. An expired or tampered link opened by a signed-in user is caught by the scoped `InvalidSignatureException` renderer in `bootstrap/app.php` (only when `routeIs('ai-report.shared')` and a user exists; every other signature failure falls through to the default handler): it redirects to `ai-report` with the session flash `ai-report-notice`, which `Main::mount` pulls and shows as a warning toast («لینک منقضی شده؛ از فهرست «دریافتی» گزارش را باز کنید.»).

## 2. Component name = tenant slot

The Livewire component name is `dashboard.ai-report.main`; `tenantOffName()` derives the module slug from it. Putting `reports` in `app.off` must NOT hide this module (and `ai-report` must not hide reports) - pinned by a test. Never rename the folder or class to `Report`/`Reports`.

## 3. Access (`AiReportAccessPolicy`, static, user nullable)

- `canView`: owner always (even when `active` is false); otherwise report `active` AND (elevated role, OR recipient who `isActive()` with `saved_at` set and status `ready`). The owner branch skips `isActive()`. An admin who is not the owner cannot open an inactive report in the user panel (consistent with `visibleTo`); Filament still shows it.
- `canGenerate`: active, non-Guest, `ReportAiService::isConfigured()` (key AND url filled).
- `canRefine`: owner, `active`, status ready or failed (a parked report cannot be refined — otherwise a generating run on a deactivated row would be invisible to every list). There is no version-count gate; `pushVersion` trims instead.
- `canSave`: owner + ready. `canShare`: owner + ready + `active` (an inactive report shows no share button and no share dialog; `ShareReportAction` re-authorizes server-side). `canRename`/`canRevert` = `canSave` AND `active` AND empty `recipients` (a shared or inactive report is frozen: no rename, no revert, no manual edit, no version rail). `canDelete`: owner and not `generating`. `canToggleActive` = `canDelete` (owner, not generating); `UpdateReportAction` maps the `active` change to it, `Main::toggleActive` is the only caller.
- `Main::updating()` aborts 403 for `form*`, `shareRecipients`, `titleDraft`, `blockDraft` writes when `readOnly` - this also catches `removeUpload('form.files', ...)`, which performs a real property write.
- **Per-block editing surfaces** (both owner-only, `actionable()`-gated): the per-block refine button (`editBlock(p:b)`) only sets `form.block` after `BlockCatalog::resolveBlock()` confirms the target exists in the spec (bad refs are silent no-ops) and dispatches `ai-report-open`; the table component's warning badge calls `editBlock(ref, true)` (the `flagged` mismatch tap, owner + `editable` only, read-only/inactive viewers get a static badge), which — when the block's `check` is `mismatch` and the prompt is blank — pre-fills `form.prompt` with `mismatchPrompt()` (names the offending columns via `BlockCatalog::mismatchColumns()`, capped to `prompt.max`); the composer then shows the target chip («فقط «X» اصلاح می‌شود», `clearBlock` undoes it), and `close()`/`select()` reset it (`open()` goes through `select()` and also empties `form.files`, so staged uploads never leak into another report). The manual editor (`openBlockEditor`) additionally requires `canRevert` (active + unshared) and fills `#[Locked] $blockRef`, `#[Locked] $editorHash` (`md5(json_encode($block))` at open) and `$blockDraft` from the stored block, then sets the public `$blockEditorOpen = true`; the dialog is `<x-ui.modals.action wire:model="blockEditorOpen" action="saveBlock">` (not an `open-modal` event), and `updatedBlockEditorOpen(false)` or a null `blockRef` runs `cancelBlockEditor()` (clears ref, hash, draft, validation). `saveBlock` sends the ref, draft and hash through `UpdateReportAction`, which re-authorizes under `lockForUpdate` and, when the locked row's block no longer hashes to `editor_hash`, throws a `RuntimeException` with code `UpdateReportAction::STALE_EDITOR` (409): `Main::run()` shows its own message («گزارش در جای دیگری تغییر کرده؛ پنجره را ببندید و دوباره باز کنید.») instead of the generic «not allowed» text and closes the editor (a stale editor can no longer overwrite another tab's finished refine). A save whose normalization would DROP a list entry (emptying a bullet/paragraph/row/item/option/label/series line — the normalizer silently skips empty lines) is rejected with the incomplete-content error instead of deleting data. `blockRef` is `#[Locked]` (client tampering throws in Livewire), `blockDraft` is guarded read-only. `resolveBlock()` in BlockCatalog is the ONE parser for `p:b` refs (Main, both actions, the presenter's `blockLabel`, the job's `mergeBlock`, `ReportAiService::userBlock` all call it) - never hand-roll the regex again.
- Public state is `#[Locked]` (`reportId` also `#[Url(as:'r')]`, `readOnly`, `listLimit`, ...); `reportId` is re-validated through `canView` on mount. `filter`/`sort`/`sortDir`/`listTab`/`pinned` are `#[Locked]` (`filter` also `#[Url]`, `f`); `activeTab` (`#[Url]`, `tab`) and `search` (`#[Url(as:'q')]`, `wire:model.live.debounce.400ms`) are the two unlocked list properties — `activeTab` must stay unlocked because the view-toggle's `:class` reads `$wire.activeTab` and its click writes the property back (a `#[Locked]` prop is not writable from the client). Neither is read-only-guarded. `activeTab` has THREE values (`TABS` = `compose|report|table`, anything else is clamped to `compose` in `mount`): `compose` = the «فشرده» style (viewer + composer with the side list), `report` + `table` = the «کلاسیک» style (tab-selector «گزارش و فرم» / «جدول گزارش‌ها», no side list on `report`). The toggle has two buttons; the second is `['value' => 'report', 'match' => ['report', 'table']]`, so it stays highlighted on both classic tabs and a click on it while already matching is a no-op (it never knocks the user out of the table).
- Read-only viewers get an empty `shareRecipients` (recipient ids are never sent to them); the "N recipients" chip shows only on the owner's own rows.

## 4. Generation flow, quota, failure

1. `GenerateReportAction`: validate form, policy, `finfo`-based staging in `stage()` (client ext/mime never trusted; every limit read through `AiReportUploadLimits`: each inline PDF/image <= `inlineKb()`, ALL inline files together <= `inlineTotalKb()` (inline aggregate cap, so the base64 request body stays bounded), grand total <= `totalKb()`; per-file size is the form rule via `perFileKb()`), pre-check quota, then `Cache::lock('ai-report:generate:{uid}')->block()` around one DB transaction (`assertIdle` = one non-stale generating report per user via `AiReport::query()->freshGenerating($uid)`, the shared scope in `HasGenerationLifecycle` — owner, `status = generating`, `updated_at` newer than `stale_minutes` — also used by `Main::hasGenerating`, `stillGenerating` and `announceFinished`; refine locks the parent row). Files are stored under `ai-report/tmp/{id}` AFTER the transaction; dispatch `GenerateReportJob` last. A store/dispatch failure calls `markFailed('exception')`.
2. **Quota** = cache counter `ai-report:quota:{uid}:{Y-m-d}` (app timezone, expires `endOfDay`), NOT a row count. `consumeQuota` runs ONCE, after the transaction and still inside the lock; a count over `daily_cap` makes `markFailed('quota')` (which refunds) plus a validation error. Deleting a report never refunds, so a generating report cannot be deleted (policy, and the admin resource blocks it too).
3. **Refund** happens ONLY in `HasGenerationLifecycle::markFailed`: the update is conditional on `status = generating` (and, for `stale`, on `updated_at` older than the window), so a refund fires exactly once. It is skipped for `config('ai_report.no_refund')` (`too_large`, `blocked`). `refundQuota` targets the day stored in the version's `quota_day` (falls back to today for legacy rows) and floors at 0 (an overlapping double refund is put back). `markFailed` reads that day from the in-memory `versions` only when the attribute was loaded; list rows come from a column-limited select (`LIST_COLUMNS`, no `versions`), so it re-reads `versions` from the DB first — otherwise a stale flip from `reports()` would refund today's counter instead of the generation day. A cached config from before `no_refund` existed throws inside `markFailed` - `config:clear` on deploy.
4. **Stale** = generating and `updated_at` older than `stale_minutes`. `Main::report()` / `reports()` flip such rows to failed `stale` (refunding); the job `touch()`es on start so a queue backlog is not mistaken for stale.
5. **Job**: `ShouldBeUniqueUntilProcessing`, `$tries = 1`, `$failOnTimeout`, `afterCommit()`. Timeout = `2 * (services timeout + connect_timeout) + padding`, clamped to `queue.default retry_after - retry_margin` (holds only while the real worker's `retry_after` matches the default connection). Missing row or status != generating: delete temp dir and return. Success is written under `lockForUpdate` only if still generating, and drops the version's `parent_spec`. `finally` always deletes the temp dir. `failed()` maps `TimeoutExceededException` to `timeout`, else `exception`.
6. Failure codes (`fail_reason`, varchar 32): `http_429`, `http_5xx`, `http_4xx`, `timeout` (connection / `unreachable` / worker timeout), `invalid_json`, `invalid_spec`, `too_large` (finish `length`), `blocked` (`content_filter`), `empty`, `exception`, `quota`, `stale`. Only `too_large` and `blocked` do not refund.
7. **Logging**: the job logs `ai-report.http` with `report_id`, `status`, `retry_after` (429 only), `type`, `code` and nothing else - never the body, message, gateway URL or key. `ReportAiService` logs nothing. Never add the URL, key or raw response to a log, toast, exception message or print view.

## 5. Provider recipe (`ReportAiService` + `BlockCatalog`)

- POST `{url}/chat/completions` (OpenAI-compatible), header `Authorization: apikey {key}` (NOT Bearer), `response_format.type = json_schema`, `strict = true`, `schema = BlockCatalog::schema()`, `temperature 0.2`.
- Schema is FLAT: one `$defs` block entry, `additionalProperties: false`, ALL block keys `required`, unused keys `null` via type arrays (`['string','null']`), NO `anyOf`/`oneOf`. Top level requires `lang`, `title`, `pages`. Bounds come from `config('ai_report.spec.*')`; the schema has no URL field.
- The gateway may IGNORE the strict schema, so `BlockCatalog::validate()` re-checks every bound server-side (`InvalidArgumentException` -> `invalid_spec`) and the system prompt's rule 0 pins the output shape (`pages[0].blocks[]` with a `type` key, never top-level parts). Do not remove rule 0 or trust the schema alone.
- Call budget `provider.max_calls` (2) is shared by the empty-content retry and the JSON repair turn; exhausting it raises `empty`.
- Attached text is fenced `<<<FILE name>>> ... <<<END FILE>>>` (`<<<`/`>>>` in name and body are replaced) and the prompt declares it data, not instructions; extractor notes go under a `SYSTEM NOTES` heading outside the fence. Inline parts: PDF as `file`, jpeg/png/webp as `image_url`. docx is read via `ZipArchive::getFromName` + `strip_tags` under a byte cap (no XML parser); xlsx/docx are zip-sniffed; formula cells without a value become empty plus one note; date cells render Gregorian plus Jalali.
- A CSV that `finfo` reports as `application/vnd.ms-excel`, plus `.xls/.doc/.ppt`, is rejected with the "use .xlsx/.docx" hint.

## 6. Version history, fork, share

- `versions` JSON holds one entry per prompt (`prompt`, `files`, `at`, `quota_day`, later `spec/model/tokens`, `skipped`, `notes`; a one-block refine adds `block` = `p:b`; a manual edit adds `manual` = true with prompt «ویرایش دستی» — the version card label gains « · دستی» and it consumes no quota). `pushVersion` keeps the last `max_versions` and sets `versions[0]['trimmed'] = true` after trimming - the UI reads that flag, never infer trimming by count.
- Refine of a report with no recipients mutates in place. Refine of a SHARED report FORKS: a new private draft row with `forked_from = parent id` (also on the version); the shared copy never changes. A failed fork keeps `parent_spec` on its version so a retry still revises the parent spec (`lastSpecVersion()` or `parent_spec` is the source for a failed row). A one-block refine carries its `block` on the fork's version exactly like a full refine; the job then sends only that block (`CURRENT_BLOCK`) with a block-mode system prompt that DROPS the `REPORT TYPE:` and `LENGTH:` lines (they contradict "exactly one block"; the audience rule stays) and forces the parent's `lang` onto the decoded reply before validation. `mergeBlock()` splices back the FIRST reply block whose type matches the original, skipping an inserted assumptions section (`validate()` adds one before a trailing callout, so block 0 of the reply is not always the revised block); no matching block = `invalid_spec`. Assumptions heading pinned; a title block also rewrites spec title. A block refine never rewrites the `preset_*` columns.
- `forked_from` is a plain nullable unsigned bigint (no FK). The create migration is a plain `Schema::create` (nothing was deployed before it, so no guarded alter branch). The three nullable `preset_type`, `preset_length`, `preset_audience` varchar(32) columns live in it and in `$fillable`; they are written and shown only once the report-preset feature lands.
- **Replace-share**: `ShareReportAction` receives the FULL desired id list (unticking = unshare, an empty list is legal). Under `lockForUpdate`, stored = requested ∩ `User::visibleOnBoard()` minus owner, sliced to `max_recipients`; `truncated` is true when eligible ids exceed the cap, and the toast then reports only the cap. Only newly added ids are notified, with ONE `temporarySignedRoute('ai-report.shared')` valid `share_link_days`; link expiry does not remove access (the list scope has no time condition). `saved_at` is set once and never cleared by unshare. The conditional update requires owner + `status = ready`.
- **Unseen badge**: `seen_by` (json ids) holds recipients who opened the report. `Main::select` calls `markSeenBy` for read-only recipients (not owners, not admins who are not recipients; an admin who is also a recipient is marked); `HasAiReportHooks` (the model's hooks trait, declared last) flushes `StateService` when a shared report is deleted or its `active` flag changes, so the dot never outlives its report; `ShareReportAction` keeps `seen_by ∩ new recipients` so a re-added recipient is unseen again, and both flush `StateService`. The dot is the `UnseenAiReports` indicator, key `ai-report-controller` (the menu row id); the share bell has no `menu_key`, so the badge sync never touches it. The column lives in the create migration (plain Schema::create, no second migration file).
- **"New" chip**: `listRow()['is_new']` = not mine and viewer not in `seen_by`; the Main list query selects `seen_by` (not part of `LIST_COLUMNS`, so the Filament select is untouched) and `listSignature` includes `count(seen_by)` so polls notice a change made in another tab or by a re-share.
- **Reuse** (`Main::reuse`): owner-only through `actionable()`; takes `versions[0]['prompt']`, closes the report, resets form and validation, pre-fills `form.prompt` and dispatches the `ai-report-open` window event (the composer listens and expands). It never starts a generation. Hidden for forks (`forked_from` set, first version is a refine text) and when history was trimmed (`versions[0]['trimmed']`).
- **Encrypted Office files**: `ComposerForm::isEncryptedOffice()` (finfo `CDFV2-encrypted`/`encrypted` always; plain `CDFV2` only for `.docx`/`.xlsx` names) gives `encryptedFileMessage()` in both the form rule (closure before `mimes`, after `bail`) and `GenerateReportAction::stage()`; a real `.doc` keeps the generic message.
- `mount(?AiReport $report = null)` receives a blank model when the route has no `{report}`; always test `$report?->exists`, never `!== null`.
- `retry` re-runs refine from the stored prompt (also restoring the version's `block` for a failed one-block refine, so a retry does not silently widen to the whole report). When the failed version had `files`, nothing is sent: the prompt (and block) are restored into the form, `ai-report-open` expands the composer and a warning toast asks the user to re-attach the files and press refine (files are never kept after a run). Otherwise `refine()` runs and a validation failure (quota used up, another run active) surfaces as a warning toast with the form reset, because the composer is collapsed. A retry is a normal refine, so it CONSUMES one quota unit (the failed attempt's unit was already refunded); the failed card says so (`ai-report-retry-quota-note`) and adds `ai-report-retry-files-note` when files were attached. A `no_refund` `fail_reason` makes `retry` a silent no-op (the failed card hides the button and shows a rewrite-the-request hint instead). The failed card also prints `failHint()` (per-cause, per-code user wording from `fail_hints` in strings.php, including the quota outcome) under `failReason()`.
- **Active toggle** (`Main::toggleActive`): owner-only through `actionable()`; flips `active` under the existing `UpdateReportAction` lock; recipients lose access with no extra code because every recipient path (`visibleTo`, `sharedWith`, `unseenBy`, `canView`'s recipient branch, the search resource) keeps `active()`. `Main::open()` resolves through `canView`, not `visibleTo`, so the owner can open an inactive row from the table's «غیرفعال‌ها» filter.
- **Lock-then-reauthorize** (all four actions): `DeleteReportAction` locks the row and re-checks `canDelete` on the FRESH row inside the transaction; `UpdateReportAction` authorizes the handle, then again on the locked row before `apply()`; `ShareReportAction` checks `canShare` up front, then inside the transaction re-derives `existing` from the locked row and writes through a conditional update scoped to owner + `active = 1` + `status = ready` (so a report deactivated or deleted between click and write is never shared), and sends the database notifications INSIDE that transaction (a rolled-back share notifies nobody). `Main::run()` rethrows `ValidationException`, turns a `RuntimeException` that is NOT a `PDOException` into the `$denied` warning toast, and routes everything else (including `PDOException`) through `report()` plus the generic `fail_toasts.exception` toast, so a database fault is never mislabelled as «not allowed».

## 7. Pollers and morph-safety (`wire:key`)

- Two pollers, never both for the same report: the side-list `<aside>` polls (`pollList`) only while the open report is not the generating one; the viewer's generating branch polls `pollStatus`. In the classic style (`report` and `table` tabs, no aside) the sibling anchor div (§7 two-views bullet) polls `pollList` instead, under the same rule: always on the table tab, on the report tab only while no report or a non-generating one is open. Both use `wire:poll.visible.{poll_seconds}s` and call `skipRender()` when nothing changed (`listSignature` / `lastSeenStatus` are `#[Locked]` and drive that comparison).
- NEVER put `wire:poll` behind an `@if` inside a tag's attribute list. The list is two keyed asides (`ai-report-list-polling` / `ai-report-list-idle`) sharing one `@include('livewire.dashboard.ai-report.list')`.
- Keys follow the project morph-safety rule: static, kebab-case, `ai-report-` prefix, one per branch root (`ai-report-viewer-empty|generating|failed|ready`, `ai-report-composer-refine|generate`, `ai-report-empty-list`, ...), per-id keys only on repeated rows (`ai-report-list-{id}` on the row button itself, `ai-report-version-{index}`, `ai-report-staged-{i}` with `-thumb-`/`-icon-` keys on its image/icon branch); multi-root branches and `<x-ui.empty>` get a `<div wire:key class="contents">` wrapper. The only tolerated `@if` inside a tag is the short boolean `disabled` on version-rail buttons. The block dispatcher wraps EVERY rendered block in `ai-report-block-{p}-{b}-{view}` (`{view}` = the resolved partial name, e.g. `table`, `kpi-row`, so a block whose type — and therefore partial — changes remounts instead of morphing one partial into another; toolbar wrapper `ai-report-block-tools-{p}-{b}`, buttons `ai-report-block-refine-{p}-{b}` / `ai-report-block-manual-{p}-{b}`; the table partial's tappable mismatch badge `ai-report-block-check-tap-{p}-{b}`); the block-editor dialog root is `ai-report-block-editor-dialog` (`class="contents"` wrapper around `x-ui.modals.action`, rendered only for an owner who passes `canRevert`) and its form `ai-report-block-editor-form` with `ai-report-block-field-{dotted}` / `ai-report-block-cell-{i}-{j}` / `ai-report-block-total-{j}` / `ai-report-block-grid` inside. The dispatcher is also included by the Filament admin preview, but `editable`/`manual` default false there, so admin previews carry no toolbar.
- List load-more: `listLimit` starts at and grows by `pageSize()` (the `SIDE_PER_PAGE` = 5 constant in the compose side list, `TABLE_PER_PAGE` = 30 in the table view; no config), clamped to `list_max`; a view switch resets it; the button shows only when the page is full and below the cap. `close()` resets the limit. The side-list header carries a count badge (`ai-report-list-total`) from the `total` computed (`listQuery()->reorder()->count()`, the full total of the open active/inactive list tab, not just the visible rows; cleared in `forgetReport()`).
- Compose-view order: viewer first, then the composer (type/length/audience selects sit above the prompt box); recipients (read-only) have no composer, so they see only the report — the viewer prints them a read-only notice-card naming the sender (`ai-report-recipient-banner`, `print:hidden`). An inactive OWNED report replaces the composer body with an activation notice-card (`ai-report-inactive-composer`; the normal form lives in the keyed `ai-report-composer-form` `contents` wrapper) whose notice-card `actions` button calls `$wire.toggleActive()` — the first and only consumer of the notice-card `actions` prop. The prompt textarea carries `dir="auto"` so an English request types left-to-right while the page stays RTL; the shared maximize overlay keeps its own fixed `rtl` container (not changed, other modules use it). Report content itself is bilingual per report (`lang` fa|en picked from the request language; direction, digits, built-in headings, disclaimer and print date follow it); every module screen and string is Persian only.
- **Composer session draft** (aiReport.js `aiReportComposer`): every `input` on the prompt textarea writes its value to `sessionStorage['ai-report:draft:{uid}']` (uid from `<html data-uid>`, try/catch-swallowed, empty value removes the key); `init()` restores a stored draft into an EMPTY textarea (server-filled textareas are never overwritten) and `$set`s it back to `form.prompt`; `submit()` clears the key only on the wire promise's success path — a 419 rejection keeps it so the `livewire-errors.js` self-heal reload restores the text; the `form.prompt` `$watch` also removes the key whenever the prompt becomes empty (including the server's post-generate reset). The composer root carries two Alpine flags: `uploading` (set by the root's `livewire-upload-start|finish|error|cancel` listeners; disables the submit button and swaps its label) and `sending` (set by `submit()` for the duration of the wire call so Ctrl/Cmd+Enter cannot double-submit; both also gate `submit()` together with `data-can-submit`). All wording stays in the blade; the JS carries no Persian literals.
- **Quota meter and rules** (composer, `print:hidden`): the meter (`ai-report-quota-usage`, `role="progressbar"`) shows `quota()` used / cap (`HasDailyQuota`, `daily_cap`), turns gold from 80 % and error-red when exhausted, with the `ai-report-quota-left` hint at >= 80 % and the `ai-report-quota-exhausted` notice-card at the cap; the «قوانین» accordion (`ai-report-rules`, `x-collapse`, one `ai-report-rule-{index}` row per group: quota, files, one-at-a-time, shared, review) is a data array in the composer's `@php` block whose numbers come from `$limits`/`quota()`, never literals. Submit is disabled when exhausted, when another report is generating (`hasGenerating`), or (generate only) when the open report is generating.
- **Generating state and completion toast**: the viewer's generating branch (`ai-report-viewer-generating`, polls `pollStatus`) shows `<x-ui.loaders.skeleton.report wire:key="ai-report-generating-skeleton"/>`, the eta line, a `slow_seconds` timer (`x-init` flips to the «can leave this page» line client-side; the value is `config('ai_report.slow_seconds')`), and echoes the prompt and file names. `Main::watchedId` (`#[Locked]`) is set by `generate()`/`refine()`; `pollStatus` clears it and toasts when the OPEN report flips out of `generating` (ready or failed via `failToast`). `pollList` → `announceFinished()` re-reads the user's `freshGenerating` id into `watchedId` and, when the previously watched report is no longer generating, toasts its outcome (`ready` / `failed`) UNLESS the user is looking at it — `$viewing = $watched === $this->reportId && $this->activeTab !== 'table'` — so the same finish never toasts twice and a user parked on the table (or on another report) still hears about it. Closing the page produces no toast (only sharing notifies).
- The prompt textarea component already prints its own `@error`; do not print `form.prompt` errors again in the composer.
- **Two styles, one query.** The style switch is `<x-ui.buttons.view-toggle responsive state="$wire.activeTab" action="toggleView" :modes>` in the title actions with modes «فشرده» (`compose`, icon `edit_note`) and «کلاسیک» (`report`, `match` = `report|table`, icon `table_rows`); `toggleView()` ignores values outside `TABS` and calls `resetList()` (the toggle's own click guard skips the call when the mode already matches). `switchTab()` is shared with the classic tab-selector (`report|table` route to `toggleView`, `active|inactive` set `listTab`). Title search uses `INSTR`, not `LIKE`. ## 8. Frontend: lazy chunk, inline print handlers, print and RTL

- Alpine factories (`aiReportComposer`, `aiReportCopy`, `aiReportTable`, `aiReportChart`) live in the lazy `ai-report` chunk (`modules/ai-report.js`, registered in `ModuleChunkComposer` and `ModuleAssetChunksComposer`); server values reach them through `data-*` attributes read at event time, so morphs stay honoured. The character counter follows `form.prompt` through `$wire.$watch`. Roots carry `x-cloak`. No Persian literals in the JS (toast text comes from `data-toast`).
- The print guard on the `.ai-report-doc` root (`x-data="{wasDark,wasTitle}"` with `beforeprint`/`afterprint` window handlers) is deliberately INLINE, not in the chunk: the same `<x-dashboard.ai-report>` component renders in the Filament admin preview, where the user-panel chunk never loads. The handlers strip the `dark` class and swap `document.title` to `data-title` for the print, then restore both.
- There is ONE print/PDF control: the `print` icon button in the title actions (`ai-report-print-button`, `window.print()`, shown only for a `ready` report outside the table tab; title/aria-label explain that «ذخیره به‌صورت PDF» is chosen as the destination in the print dialog). The former separate «ذخیره PDF» button no longer exists. The copy button (`ai-report-copy-button`, `x-data="aiReportCopy"`) sits beside it, and `ai-report-reports-link` (`show_chart`, `route('dashboard', ['tab' => 'reports'])`, `wire:navigate`, wrapped in `@unless(tenantOff('reports'))`, title «گزارشات سازمانی») links to the separate Reports module.
- **Letter card** (`ai-report-letter`, `print:hidden`, owner and recipients, READY branch of the viewer only, above `<x-dashboard.ai-report>`): `AiReportPresenter::letter($spec)` builds it from the saved spec alone (no block, no model call, no quota) and returns `null` unless the title and at least one other part exist. Parts: title block heading (spec title fallback); ONE key figure = first item of the first `kpi_row`, else of the first `facts`; decision = heading + first paragraph of the first `variant: decision` callout; assumption = first paragraph (else first bullet) of the section matched by `BlockCatalog::isAssumptionsHeading`. Labels follow `spec.lang` (assumptions label = `ai_report.assumptions.heading.{lang}`), root `dir` = `dir()`. Partial `ai-report/letter.blade.php`, keys `ai-report-letter`, `-figure`, `-decision`, `-assumption`, `-copy`; the copy button (`aiReportCopy.copyLetter()`) copies its `data-text` (the presenter's plain-text lines) with `data-toast`, independent of the DOM collector.
- `aiReportChart` keeps a `failed` flag: a throwing `build()` (or a missing `window.Chart`) sets `failed = true`, releases the instance and stops every later `redraw()` until the next `beforeprint`/`afterprint` handler clears the flag, so a broken chart does not retry on every ResizeObserver/theme tick.
- Print contract is the `@media print` block at the tail of `resources/css/core/dashboard.css` (colour/break/header rules) PLUS an inline `<style media="print">@@page { size: A4; margin: 14mm; @@bottom-center { ... } }</style>` as the first child of `.ai-report-doc` in the dispatcher (the `@@` escapes Blade; `@page` is NOT in dashboard.css any more — it travels with the document, so the user panel and the Filament preview share it), gated by `body:has(.ai-report-doc)`: everything outside `#content-shell` and every `print:hidden` is hidden, forced black on white with `print-color-adjust: exact` (and the prefixed `-webkit-print-color-adjust`), `.ai-report-page + .ai-report-page` breaks before, rows never split and `thead` repeats, `.ai-report-keep` (`break-inside: avoid`) only on short units (title, KPI grid, highlight, callout) - never on tables or whole pages, the inline `@page` is A4 14mm and also declares `@bottom-center` page numbers (`counter(page) " / " counter(pages)`, Latin digits — accepted): Chromium ≥131 fills the margin box; Firefox/Safari drop it silently (accepted — margin boxes cannot carry per-report text). The print header `.ai-report-print-head` (owner · date, fed by the dispatcher's `author` prop, `<bdi>` name, Jalali `j F Y` in `fa` specs / Gregorian `j F Y` in `en` specs) is a normal first-row element on the FIRST page only (accepted — a repeat on every page would need a fixed-position CSS-variable hack, unreliable cross-browser), carries `aria-hidden="true"` (the copy collector §8 ignores it) and is never `position: fixed`. Because the `@page` block is an inline print `<style>` in the document, the Vite/Lightning CSS pipeline never touches the margin boxes. `Main::report()` eager-loads `user:id,name` for it; the Filament infolist preview passes the owner too, and the admin preview's doc shows the same header on print.
- RTL/LTR is decided once by `AiReportPresenter::dir()` from `spec.lang` and set on the doc root. Table alignment: header and body cells use `text-start` (logical, flips with the root `dir`), NO per-cell `dir="auto"` (it flips each cell by its first character and scrambles column alignment); cell text goes inside `<bdi>` so mixed digits/Latin do not reorder punctuation. Numeric cells add `tabular-nums`. Free-text paragraphs may keep `dir="auto"`. All output goes through `{{ }}`.
- The summary card (`ai-report/letter.blade.php`) is an accordion that is CLOSED by default (2026-11-07): `x-data="{ open: false }"` sits AFTER `dir` on the keyed root because `test_an_english_report_uses_english_letter_labels_and_ltr` asserts the exact substring `wire:key="ai-report-letter" dir="ltr"`; the title and a chevron toggle it, the copy button stays in the always-visible header, and «رونوشت خلاصه» reads `data-text`, not the hidden DOM, so collapsing never changes what is copied.
- The copy collector (`collectReportText`) reads the DOM structure (skips `aria-hidden`, `print:hidden`, `.ai-report-disclaimer` and spans without a `bdi`; keeps option letters and every KPI tile paragraph) - a block-markup change can silently change copied text.
- Block partials carry no `wire:key` and no interaction; unknown block types are dropped by the dispatcher.
- The table never prints (`print:hidden` roots); the print contract stays compose-only.

## 9. Admin (Filament, read-only)

`AiReportResource`: `canCreate()` false, pages `index` + `view` only. Record actions: view and delete (hidden when generating); bulk delete cancels if any selected row is generating; the active switch (`activeColumn`) and `bulkVisibilityActions` come from the shared Filament traits - an inactive report disappears for recipients and for non-owner admins in the user panel; the owner still sees it under the table's «غیرفعال‌ها» filter and can re-enable it. The table selects `LIST_COLUMNS + active, model, tokens_total, created_at`; the owner is eager-loaded as `user:id,name`. The infolist previews with the SAME `<x-dashboard.ai-report>` component and presenter `dir()`. `last_prompt`/`skipped_files` are admin-only. Navigation is hidden when `app.off` lists the module (`tenantOffName`), while the generic `ReportResource` is available to the user, and when the user lacks `canViewAny()`. The resource is reached from `ReportResource` through the `FilamentResourceSwitch` buttons.

## 10. Cache classification

`AiReport` is Tier L in `app/Models/modelPattern.md` (generation status is live and polled): no cached option lists, no cross-request caching of rows. The only cache keys are the quota counter and the generate lock. Share candidates come from the already-cached `User::getCachedActiveOptions()`.

## 11. Gotchas

- Never log, print, toast or return the gateway URL or key; they live in `.env`, and `config:clear` is needed after changing them.
- `finfo` decides file kind; `.xls`/legacy Office are unsupported by design.
- Temp files are deleted on success, failure and early return, and by `HasAiReportHooks::deleteStagedUploads` on ANY model delete (user, admin single and bulk delete), so `DeleteReportAction` carries no delete of its own; a refine needs its files re-attached. Anything that still slips through is swept by the app-wide `storage:prune-tmp` (daily 04:35, config `filesystems.tmp_prune`; allowlisted roots, age-only, symlink-safe).
- Test fixtures must set `active` explicitly: a row created through `create()` has no `active` attribute in memory until refreshed, so `canView` reads it as false. The mirror also bites: after an action mutates the row through a different instance (e.g. `toggleActive`), pass `->fresh()` to any later `mount`/`open` in the same test — a stale in-memory handle still carries the old flag.
