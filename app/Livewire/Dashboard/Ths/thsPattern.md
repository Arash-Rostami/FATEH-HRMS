# Ths (ticketing) — user panel `Main` / `Workspace`, actions, mirror task

Created 2026-10-09 with the task/project overhaul; earlier Ths behavior is documented in `app/Services/Menu/statePattern.md` (ThsNudge/ThsBadge) and `app/Filament/filamentPattern.md` (admin `ThsResource`).

1. **Rulebook:** every ticket permission is `App\Support\TicketAccessPolicy` (`app/Support/supportPattern.md` §3). A HEAD is `User::isHeadOfDepartment($code)` — ties-aware (`User::headsOfDepartment`, cached 1h, bumped by `Profile::saved`), so two equal-rank people are both heads. Target department = `Ticket::effectiveTargetDepartment()` (`extra.target_department`, else the default one); the department filter is `Ticket::scopeTargetedAt`.
2. **Lists:** `Main::$listFilter` is `mine | actionable | department`. «department» (heads only, `isHead` computed, 403 otherwise) lists every ticket targeted at the head's department in any status, with `statusFilter` (all/open/in-progress/closed); `actionable` (inbox) = in-progress assigned to me + `awaitingRatingBy` + (heads) open tickets of the department. The rating prompt uses `Ticket::awaitingRatingBy`; a withdrawn ticket (`action_result === Ticket::WITHDRAWN_RESULT`) is never prompted.
3. **Workspace actions** (each in its own Action, `DB::transaction` + `lockForUpdate` re-check of the policy): `WithdrawTicketAction` (requester, open/in-progress -> closed with the withdrawn result), `RerouteTicketAction` (elevated/head, not closed: new department + required note, status back to open, unassigned, reply «ارجاع به …»), `ReleaseTicketAction` (assignee of an in-progress ticket: back to the queue with a required note, reply «بازگشت تیکت به صف»), `AssignTicketAction::execute($ticket, $assigneeId, $actor, $seenStatus)` (assignee must be in `Ticket::assignableUsers()` = active board users of the target department; `Workspace::$seenStatus` is a `#[Locked]` guard so a second head assigning an already-taken open ticket gets «این تیکت قبلاً محول شده است»), `AssignTicketAction::close()` (policy `canClose`, atomic with marking the mirror task done). `SubmitTicketAction` has a 10-second `Cache::add` double-submit guard; `TicketForm` validates type/area/department against the option lists.
4. **Closed is final:** `Ticket::saving` rejects reopening and assignee changes of a closed ticket; `completion_date` is stamped when it closes (user panel too — it used to be admin-only). Replies are blocked on closed tickets (`canReply`), a closed-and-rated ticket no longer nudges.
5. **Mirror task** (`tasks.ticket_id`): created `todo` with the ticket deadline, department and `action_source` «تیکت»; the first assignment AND every reassignment (changed assignee, or a previously released/trashed mirror coming back) set it to `todo` — the doer moves it to `in-progress` themselves; an unchanged assignee keeps the current status and a `done` mirror is never touched by assignment syncs; unassigning (release/reroute/admin) SOFT-DELETES it (re-assigning restores the same row — no duplicates, `lockForUpdate`); closing marks it done. `Task::guardTicketLock` makes it read-only for everyone except code running inside `Task::syncingFromTicket()` (all ticket-side writes are wrapped in it). Deleting a ticket deletes its mirror task and replies; `Ticket::updated` mirrors `completion_deadline` to the task deadline.
6. **Assignee picker avatars (2026-10-14):** the picker chip, each candidate row and the reply-bubble sender use `<x-dashboard.user-avatar>` (online dot, status badge, yoga icon on focus), so `Workspace::assignableUsers()` selects `presence`, `status`, `last_seen`, `focus_until` on top of `id`/`name` (an omitted `last_seen` silently forces the dot offline). Candidates on leave/mission also carry `<x-ui.presence-tag>` («پاسخ‌گو نیست») — a warning only; `AssignTicketAction` never checks presence.
7. **Mine-queue sort (2026-10-15):** `Main::$sort` / `$sortDir` (created|subject|status|priority, default created desc) via `sortBy`/`resetSort`, both resetting `perPage`; `SORT_COLUMNS` is the whitelist and `sortExpression()` orders priority (low<medium<high) and status (open<in-progress<closed) with `FIELD()`, then `id desc`. Only `tickets()` (the mine query) honors it — like `ticketSearch` and the date span; the actionable/department queries keep their own order. UI: sort popover + clickable «شناسه / تاریخ» and «موضوع» headers, mine queue only (viewPattern §8.32 toolbar paragraph).
8. **Admin parity** comes from the same `Ticket::saving/saved` hooks (assignee validation, closed lock, mirror sync), so `EditTicket`/`TicketsRelationManager` no longer need their own rules; they only read `Ticket::assignableUsers()` for the assignee select. The admin Edit select adds the saved assignee to its options ONLY if that user still exists (`$record->assignee`), so an `assigned_to` pointing to a deleted user no longer crashes on a null option label.
9. **Known glitch — maximize hides load-more (2026-10-16, accepted by the user):** the `max-widget` wrapper sits inside `ths/ticket-table.blade.php` around the `<x-ui.table>` ONLY; the `ths-load-more` button («بارگذاری بیشتر») and the «نیاز به اقدام من» / department toggle row stay outside it (by decision, so the maximized view is just the table). Consequence: while the table is maximized the user cannot load more rows (page size 10) — restore first, then load more. If this ever needs fixing, keep the button reachable by pinning it inside the widget or by replacing it with scroll-based loading; do not widen the wrapper back to the toggle row. The Reservation avantgarde grid has the same glitch (reservationPattern «Known glitch — maximize hides load-more»); fix both together if either is ever fixed.
10. **Type/area labels (2026-10-16):** tickets store the KEYS (`request_type`, `request_area`); every label comes from ONE resolver in `HasTicketOptions` (`getCustomRequestTypeLabel` / `getCustomRequestAreaLabel`), exposed as the `Ticket` accessors `type_label` / `area_label`, which pass `effectiveTargetDepartment()` (stored `extra.target_department`, else `defaultTargetDepartment()` = first of PS/BS with heads) — never read `$requestAreaOptions` directly for display (`getRequestAreaOptions()` and the old «یافت نشد» literal are gone). Area order: target dept exact type -> target dept any type -> system same type -> system any type -> any dept's custom label -> raw key; type order: system label -> target dept custom -> any dept custom -> raw key, so an unknown or orphaned key (an option key renamed in `Department::ticket_options`) shows its raw key and the data is never rewritten. Keys are matched through `normalizeOptionKey` (ي/ی, ك/ک, ZWNJ, whitespace, case). No process-lifetime `static` memo: the resolver re-reads `Department::getCachedModels()` each call, so a department edit applies immediately (same `once()` hazard as cachePattern). Icons: target dept's own first, system icon next, another dept's custom icon only if the key is custom everywhere. Admin: Area column visible by default beside Type; both sort by label and search by raw key OR any label (`searchRequestKeys`); type/area filters = system + all departments' options + every distinct value present in tickets (`distinctTicketValues`, `ModelCacheVersion` on `Ticket`); `ThsExporter` keeps the label columns and adds `request_type_key` / `request_area_key` for stable stats. User panel: the list row shows a type pill above the area, the modal shows the type next to the area.
11. **Known glitch (fixed 2026-10-16, keep as a rule) — maximize state vs lazy-loaded modules:** modules rendered through Livewire's lazy/defer mount (TaskBoard, Energy chart, Feed/Home panes, Project) are initialised by the morph BEFORE their children exist. A `restoreMaximize` that looks for `[data-widget]`/`[data-column]` at that instant found nothing and its "not found" branch deleted `max:<scope>:<uid>`, so a maximized widget never survived a reload (the console trace showed `restoreMaximize` → `_persistMaximize(null)` during `morph`). `mixins/maximize.js` `initMaximize()` now defers the restore with `$nextTick`; any new `restoreMaximize` must tolerate running after the DOM settles and must never clear the key on a first miss. Companion glitch (fixed): wrappers entrance-animated with fill-mode `both` trap `position: fixed` overlays — see scriptPattern §21 «Maximize trap». Maximize itself depends on no ancestor keeping a transform (see scriptPattern §21: page-wrapper entrance rules use fill-mode `backwards`, never `both`).
13. **PM/QA audit fixes (2026-10-16):** (a) **Per-reply bell rows** — a separate `ThsReplyNudge` (key `ths-controller:reply-nudge`) uses the REPLY as subject (item_id = reply id, so a dismissed row no longer silences later replies); `ThsNudge` keeps only the ticket-level row and no longer listens to `Reply`. (g) `AssignTicketAction::execute` writes the system reply «تخصیص به {name}» (one per assignment, also on re-assign; it is part of `action_result` and nudges the requester). 12. **Ticket insights (2026-10-16):** ONE service, `App\Services\Ticket\TicketInsightsService` (plain arrays, no Livewire/Filament state), feeds the admin infolist AND two user-panel hints — never a second implementation. **Admin** (`ThsResource::infolist`, tabs «تحلیل تیکت» / «خلاصهٔ واحد», read-only `ViewEntry`s `TicketInfolistPresenter::ticketInsights()/departmentInsights()` -> `resources/views/filament/resources/ths/insights/{ticket,department,cards}.blade.php`; there is NO View page — the infolist is the list's view modal, so «related tickets» link to the edit page). `forTicket()` (computed on open, ~4 queries): age/status; duration = `completion_date - created_at` (closed) or running age, as a ratio to the MEDIAN of closed tickets of the same target dept + type + area (fallback type, then whole dept, each needing >=3 samples excluding the ticket itself, withdrawn tickets excluded; green <=1.25x, yellow <=2x, red above); deadline (on time / late by N / none; closed without `completion_date` counts as on time); first response = first reply by someone other than the requester; owner (name, «کاربر حذف‌شده» when `assigned_to` points to a missing user, reply count, requester+assignee file count); the requester's other non-closed tickets; the last 5 same dept+type+area tickets. `forDepartment($dept)`: 90-day window by `created_at` over `targetedAt($dept)` (legacy tickets resolve to `defaultTargetDepartment()`, a null dept returns `null` = short empty message): open/in-progress/closed counts and tickets per week (total/12.86), median + p90 of time-to-close (withdrawn excluded), median first response, backlog (non-closed older than 7 days) and unassigned open — these two cover ALL non-closed tickets, not just the window —, top-5 type/area by count and by average close time (>=2 closed; labels via `getCustomRequestTypeLabel/AreaLabel` with the dept code), top-5 assignees open vs closed (deleted-user safe), average satisfaction and effectiveness (numeric 1-5 only).
