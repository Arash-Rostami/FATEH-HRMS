# Correspondence Module Pattern Guide (مکاتبات)

Official letters (`/correspondence`): outgoing and incoming, written simple or with AI (Smart mode), routed to approvers (sign) and readers (FYI), numbered on approval, printed on a letterhead, delivered to outside people by private link and/or PDF. Livewire v4, Filament v5 (read-only letters + letterhead CRUD), Laravel 12, PHP 8.2. General rules: `app/Livewire/livewirePattern.md`. Sibling to AI Report (`reportPattern.md`): it reuses the same AI concerns and the same two-styles/one-query list; only the differences are written here. Wording is Persian only.

### Main vs Workspace (Ths-style parent/child, 2026-11-10)

- **`Main`** (page, list): `activeTab` (`tab`), `listTab`, `filter` (`f`), sort, `search` (`q`), `pinned`, load-more, `letterId` (`#[Url(as:'r')]`, locked), locked `replyToId` + `epoch`, `watchedId`, batch/template state, `open/close/blank`, `useTemplate/flipTemplate/createBatch/shareBatch/templates/recentTemplates`, `pollList`, `announceFinished`. `open()` is the ONLY place that decides a letter may be shown (`canView` then `canRegistry`, else toast + `close()`); on success `select()` sets `letterId`, moves `activeTab` off `table` (compose stays, anything else becomes `report`), clears `listSignature` and, when the id is already open, sends `correspondence-reload` to the child; `open()` adds the `correspondence-open` scroll event for `canView` letters only. `close()` clears `letterId`/`replyToId` and bumps `epoch`; the child owns every per-letter reset.
- **`Workspace`** (`WithFileUploads`, `LetterForm`, the `updating()` 403 guard, `LETTER_TEXT`, every `*Letter` transition, save/rename/blocks/parties/tags/attachments/template-save, reply/copy/correction, generate/refine/retry, `pollStatus`, computeds `letter/quota/people/letterheads/incomingDuplicate/composer/generatingId`). Receives `letterId` and `replyToId` as mount params, re-runs the same access check in `load()` (mount, `reload`, after every transition) and keeps its own locked state.
- **Mounted** from `correspondence.blade.php` in both layouts as `<livewire:dashboard.correspondence.workspace :letter-id :reply-to-id :key="'correspondence-workspace-<layout>-'.$epoch">` (the two tags MUST carry different `<layout>` words, `report` and `compose`: with an identical key Livewire sends only a stub for the child when the view toggles between the two layouts, because they sit under different keyed parents, and the letter pane stays blank). Within one layout `epoch` is the only remount trigger: `close()`/`blank()`/reply bump it, and `select(int $id, bool $keepChild = false)` bumps it when the id differs (`$same || $keepChild || $this->epoch++`), so "new letter", "blank", "open another", copy-as-new, correction, template use and generate/refine/retry (which announce `watch=true`) all reset the form. Opening the already-open letter only dispatches `correspondence-reload`. `letterUpdated` passes `$keepChild = ($watch === null && $this->letterId === null)`: the first save of a new letter no longer remounts the child, so nothing typed after Save is lost.
- **Child → parent events** (all browser-callable, so the parent re-checks access): `correspondence-letter-updated` (`id` = open letter or null, optional `watch` true/false = start/stop announcing the generation) fires after every change; `Main::letterUpdated` refreshes the list, follows a new id through `access()` (copy, correction, AI fork, first save) and closes on null (delete, unavailable). `correspondence-reply` (`id`) makes `Main::startReply` clear `letterId`, store `replyToId` and remount; the child's `mount` re-validates the parent letter with `canView` before pre-filling.
- **Parent → child**: `correspondence-reload` (sent when `open()`/`useTemplate` targets the letter that is already open) calls `Workspace::reload()`, i.e. the old "re-open the same letter" semantics (form reloaded from the DB, per-letter text kept). The composer's «نمایش آن» button uses `$parent.open(...)`.
- **Confirm listener**: `x-on:confirmation-confirmed.window="{{ confirmDialogListener([...]) }}"` sits on the `Workspace` root (it carries an empty `x-data`, otherwise `$wire` would resolve to the parent). `correspondencePage` (root of `Main`) keeps only scroll, print, dialogs. The print button lives in the viewer toolbar (it needs the letter status, which only the child knows). The list poller (`pollList`) runs while a Smart run of mine is generating a letter other than the open one, or the open one while the table tab hides the Workspace; `pollStatus` runs in the child. Toggling compose/report/table remounts the child (the layouts are different parent subtrees): a saved letter reloads from the database, unsaved text, uploads, an open block editor and the sign code are lost, and an in-flight save/generate still completes on the server (the composer's «elsewhere» banner then offers «نمایش آن»).
- **Tenant guard**: `AppServiceProvider` aborts 404 per component name on `livewire.update`; `dashboard.correspondence.workspace` maps to the same `correspondence` slot as `Main`, no extra wiring.

**Event caps.** Lifecycle actions (`LetterFlow::LIFECYCLE_EVENTS`: shared, approved, approved_instead, rejected, withdrawn, voided, superseded, closed, registered, routed, printed, wet_signed, delivered_manually) may fill up to 1000; everything spammable (commented, rerouted, corrected, edited, opened, sent, link_revoked) stops at 900, so a spammer can never crowd out a lifecycle event. At the cap `LetterFlow::log` throws `too_many_events`; `edited`/`opened`/`sent`/`link_revoked` are skipped silently. `edited` by the same user within 10 minutes collapses into one entry.

### `letterheads`
`kind head|registry`, `name`, `size a4|a5|fit`, `lang fa|en`, `header_image`/`footer_image`/`stamp_image` (PUBLIC disk, `letterheads/…`), `watermark`, `margins` (cm; defaults by size, A4 top 6.0, A5 top 4.5, others 2.54), `sender_block`, `page_numbers`, `style` (font/sizes/line-height/indent, `Letterhead::defaultStyle()`), `fields_box` (side/top_mm/offset_mm/font_size), `config` (`Letterhead::defaultConfig()`: `prefix`, `header_from`/`footer_from` borrow ids, header/footer heights, repeat flags, signature/stamp/cc position, table border/repeat_head, page-number format, watermark opacity), `sign_layout 1|2|3` (stored and snapshotted but NOT read by the paper: only the last approver's signature prints, so the admin select is hidden until multi-signature printing is decided), `active`, `parent_id`, `pattern`, `start_at`, `counters` (never fillable). `registry` rows hold only name/size/lang/numbering (incoming mail, no page setup). `Letterhead::kindLabels()` is the label source for the admin. All page options live on this row, so a new option needs no migration.

## 3. Statuses, roles, modes

Consts on `Correspondence`: `draft, generating, failed` (= `DRAFT_LIKE`), `saved, shared, approved, rejected, withdrawn (reserved constant: withdraw returns the letter to draft, nothing sets it), void, superseded` and incoming `received, routed, done`. `classification normal|confidential|secret`, `urgency normal|urgent|immediate`, `sign_mode electronic|wet`, `route_mode sequential|parallel`, `sender_category normal|authority` (incoming only), `mode simple|smart`. Roles per person per letter: `approver` (reads, comments, EDITS while `shared`, signs; the last approver is the final signer) or `fyi` (reads, comments; optional `print_in_cc` prints the name in the paper's رونوشت list). Types are config (`ai.correspondence.types`, `enabled` flag, `direction`, `code` for `{TYPE}`, `counterparty_signature`, fixed `opening`/`closing`); memo/notice/minutes ship disabled.

### Transitions (one `*LetterAction::execute($id, $payload)` each, run through `LetterFlow::run` — one transaction, `lockForUpdate`, authorise again on the locked row)

Outgoing (`direction=out`):

| Transition | Who | From → to | Notes |
|---|---|---|---|
| `share` | author | draft/saved/rejected → shared | needs parties+≥1 approver, subject, body, deadline not past, no unfilled placeholder/merge token, active `head` letterhead, valid route (distinct active users), electronic: every approver has a stored signature image. Signatures reset unless it is a "resume" share whose content hash still matches `meta.resume`. Sets `shared_at`, `step_no/steps_total/awaiting_user_id`. |
| `approve` | anyone who `canView` | shared → shared \| approved | signs the awaiting approver (sequential) or own slot (parallel). Not the awaiting person → needs THAT person's sign code (§6). Repeat by an already-signed approver with a blank code is a no-op. Last signature runs `finalize` (§7). |
| `reject` | an approver (sequential: the awaiting one) | shared → rejected | reason required (≤500); optional `resume` keeps other signatures if the content stays unchanged. |
| `withdraw` | author | shared → draft | clears signatures, awaiting, `shared_at`. |
| `reroute` | author | shared → shared | rebuilds the route; already-signed approvers are kept; recomputes hash. |
| `comment` | `canView` | shared/received/routed (`Correspondence::COMMENTABLE`) | ≤1000 chars, ≤500 per letter. |
| `void` | author | approved → void | number is kept. |

## 4. Access (`CorrespondenceAccessPolicy`, static, user nullable)

- `canView`: live user and letter not trashed; author always; others only when status is not draft-like/saved AND they are in `recipients` or have a party entry. Admin panel has no user-panel access; admin sees only through Filament (§13).
- `canEdit`: author while draft-like/saved/rejected; approver while `shared` (parallel: several may edit; every content change resets signatures).
- `isRegistry` = active user with `extra.admin.correspondence_registry` truthy (admin toggle «مسئول ثبت نامه‌های دریافتی»). `canRegistry`: registry clerk may open (metadata-only, `registryOnly`/`readOnly`) a letter in `CorrespondencePresenter::REGISTRY_STATUSES` she cannot otherwise view; confidential/secret subjects show «نامه محرمانه» and no content. `canSteward`: author, or registry clerk on a normal letter (or one she can view).
- `Workspace::updating()` aborts 403 for `form*` writes when `readOnly`. State is `#[Locked]`: in `Workspace` `letterId`, `readOnly`, `registryOnly`, `contentHash`, `awaitingId`, `correcting`, `replyToId`…; in `Main` `letterId` (also `#[Url(as:'r')]`), `listTab`, `filter`, sort, `pinned`, `replyToId`, `epoch`, `watchedId`. `activeTab` (`tab`) and `search` (`q`) stay unlocked like AI Report.
- Confidential/secret: Smart mode refused, link/PDF-email refused, `search_text` null, subject hidden from non-authors everywhere (list, search, bells use `confidential_subject`, Filament masks subject/text/reason).

## 5. Frozen content, hashes, concurrency

- **`LetterRules::contentHash`**: sha256 of the key-sorted JSON of `subject, type, direction, urgency, letterhead_id, classification, sign_mode, route_mode, sender_category, spec, parties` where `parties` goes through `LetterForm::partyRows` (only the blank-party keys: identity/role/delivery/order — NOT `signed_at`, tokens or delivery state). Not covered: number/dates, deadline, tags, related link, their_number/date, meta.
- **`LetterSeal::frozenHash`** (set at approval, replaces `content_hash`): the same hash, and — only when the spec has files under `correspondence/{id}/` (attachments + image blocks) — sha256 of `hash|path:sha256(file)…` so a swapped file is detectable. A letter without files has `frozenHash == contentHash`.
- **Optimistic concurrency**: the client sends `expected_hash` (saves, block saves) and, for the guarded transitions (`share, approve, reject, reroute, correct`), `expected_hash` plus `expected_awaiting` (sequential only). A mismatch throws `RuntimeException` code `LetterRules::STALE` (409): `Main::run()` shows «در جای دیگری تغییر کرده» and reopens the letter. A save/`block_hash` mismatch on one block is the same 409. There is no lock column. Missing/blank hash or a letter with no stored hash skips the check.
- **Any content change on a non-draft letter** clears every approver's `signed_at` (`LetterWrite::commit` → `withoutActs`) and re-derives `step_no/awaiting_user_id`; every change is a new version attributed to its author.

## 6. Sign-on-behalf code (`ApproveLetterAction::verifyCode`)

The code lives only as `Hash::make` in `users.extra.admin.sign_code_hash` (protected key, §12). Flow: clicker is not the awaiting/target approver → payload `code`; empty or >72 bytes → uniform `wrong_code`. Limiter keys `sign-code:pair:{actorId}:{targetId}` (`sign_code_pair_attempts`, 5) and `sign-code:actor:{actorId}` (`sign_code_actor_attempts`, 15) per `sign_code_minutes` (15); either key full → `too_many_attempts`. Both count only the actor's own attempts, so a colleague can lock only herself out, never the target manager; the actor key is never cleared on success, so a valid code for one manager cannot reset the budget used against others. A wrong code records its strike for BOTH keys **inside the row lock, right before the error is thrown** (the limiter is cache-backed, so a rollback cannot erase it, and the next attempt waiting on the lock already sees it); `$strikes` stays only as a fallback replayed in the `catch` if something throws between arming and the check; success clears ONLY the pair key and drops the pending strikes. `sign_code_attempts` (5) now serves only the Profile card limiter. Sequential letters: on-behalf only for the awaiting approver (`viewerState.other`). Parallel shared letters: any viewer who passes `canView` may sign for another unsigned approver; `viewerState.targets` (id => name, unsigned approvers except the viewer) fills the select bound to `Main::$signTarget` (0 = self, only offered when the viewer is an unsigned approver; reset with `signCode` after approve, on open and on dialog close), and `approveLetter` sends `target_id` only for parallel letters with `signTarget > 0`. The server stays the authority: `ApproveLetterAction` accepts a target only if it is an unsigned approver other than the actor and verifies that person's code under the limiter; a non-approver, already-signed, missing or non-positive target gives `not_awaiting` (non-positive from an unsigned approver just signs as self). The error is identical whether or not the target has a code (a dummy `Hash::make` equalises timing); the target must be an active user. Event `approved_instead` records who signed for whom (never printed on paper). Own code card: Profile → Credentials (`SaveSignCodeAction`, limiter `sign-code:profile:{id}`, needs the current password, min length `sign_code_min_length` 6, ≤72 bytes, may not equal the password, `clear()` supported, never returns or shows the hash).

## 7. Approval, numbering, snapshot

`finalize` (inside the approval transaction, under the row lock): a `head`-kind letterhead is required (`share()` requires an ACTIVE one; `finalize()` deliberately does not, so a letter already in the signing route can finish after an admin deactivates the letterhead, numbering from its series); electronic → every approver's signature image must still exist (`signature_missing` names the culprits) and is COPIED to `correspondence/{id}/signature-{uid}.{ext}`; `Letterhead::nextNumber($context)` (below); `letter_date` = Jalali date (Asia/Tehran), `approved_at=now()`, `status=approved`, `awaiting_user_id=null`, `meta.snapshot`, `content_hash = frozenHash`. Files copied in the transaction are deleted if it fails (`$copied`). A unique-number collision (SQLSTATE 23000) becomes `number_unavailable`. No mail/PDF/HTTP inside the transaction.

**Numbering** (`HasLetterheadNumbering`): the lock order is correspondence row → ROOT letterhead row (`parent_id` child shares its parent's pattern, counters and prefix). Pattern tokens `{PREFIX} {DEPT} {TYPE} {YYYY} {YY} {MM} {SEQ} {SEQ:n}` (must contain `{SEQ}` on a root; ≤120 chars; `{YYYY}`/`{YY}`/`{MM}` are Jalali from the approval moment in Asia/Tehran, so the counter resets at Nowruz; `{DEPT}` = lowercase author department code, `{TYPE}` = type `code`, `{PREFIX}` = `config.prefix`). The counter key is the values of the tokens present in the pattern (`counters` JSON: `"1405|ps": 17`); editing literal text or width never opens a new scope, adding/removing a token does. `start_at` only moves forward (`max(counter, start_at-1)+1`); admin button «ادامه از آخرین» uses `lastNumber()`. A taken number (including soft-deleted letters) or a unique violation advances the sequence, up to 25 tries; a number longer than 64 chars or no `{SEQ}` fails with `number_unavailable`. `preview()` is read-only. Void letters keep their number; failed approvals roll back with no gap. Incoming uses a `registry` letterhead the same way at `receive`.

## 8. Letterhead snapshot (`meta.snapshot`)

Taken at approval so later letterhead edits never change an approved letter: `images {header,footer,stamp}` (borrowed header/footer resolved, copied from the public disk to `correspondence/{id}/letterhead-{slot}.{ext}`), `taken_at`, `frame {opening, closing, counterparty}` (type frame frozen), plus the letterhead body inline (`letterhead_id,name,size,lang,page_numbers,watermark,sign_layout,margins,sender_block,style,fields_box,config`) or, above 16 KB, `file` = `correspondence/{id}/letterhead.json`. `CorrespondencePresenter::paperData` reads the snapshot when present and the live letterhead only for unapproved letters. Old signature/letterhead edits therefore never alter an approved letter; the PDF cache hash includes the snapshot minus `taken_at`.

## 9. Body: sanitizer pipeline, limits, files

> **How files reach the screen** (grade 3 of the file protection grades, `app/Http/httpPattern.md` §7)
> - Every letter file sits in a private folder; there is no public address for it.
> - The permission check happens when the letter is drawn: staff by login, an outsider by the secret link.
> - One helper (`privateSrc`) writes a temporary signed pass for every picture inside the letter: staff 1-2 hours, outsider 10 minutes; the framework checks the stamp on its built-in `/storage/{path}` route.
> - Attachments and the PDF are different: the click goes to the app, which checks permission again and then sends the file.
> - Rule of thumb: pictures inside the letter use a temporary pass, files you click use a permission check.

Order for a block's HTML (`LetterBody::oneBlock` → model): block count ≤ `max_blocks` (60) → `html` > `HTML_BLOCK_BYTES` (65000 = `ContentSanitizerService::MAX_BYTES`) rejected → `ContentSanitizerService::clean` → `Correspondence::sanitizeHtml`: re-check 65000 → canonicalise (strip comments/PIs, escape stray `<` and bare `&`, cap `CANONICAL_MAX_BYTES` 300000) → strip raw-text elements (script, style, svg…; >20 occurrences rejected) → depth/tag-count guard (depth 100, 6000 tags) → Symfony `HtmlSanitizer` (allow p br strong em u s ul ol li h2-h4 blockquote hr sup sub mark table parts span; `a[href]` http/https/mailto only, href ≤2048 bytes, forced `rel=noopener` + `target=_blank`; `style` limited to color/font-size/font-family/text-align, `background-color` (hex, th/td/p/span/mark only), `margin-right`/`margin-left` (exactly 24/48/72/96/120pt, p/h2-h4 only = paragraph indent) and `page-break-after: always` (hr only = page-break node) with value patterns and size ceilings; `dir` rtl/ltr/auto; colspan/rowspan; img, svg, form… dropped). ZWNJ (U+200C) survives `ContentSanitizerService::clean` and the sanitizer. The `saving` hook repeats the whole pipeline for any block whose HTML is not already in the stored spec (stored HTML is trusted, so re-saves stay cheap), then enforces `body_bytes` (200000) on new bytes and `spec_bytes` (400000) on the JSON. `search_text` (≤16 KB, plain text) is rebuilt on spec/classification change, null unless `normal`.
Plain text blocks: tags stripped (≤20000). Subject/headings/captions go through `plain()` (hidden bidi/control chars removed). Images: a separate `image` block whose `path` is OUR path, never an `<img>`; uploads use `finfo` mime vs extension, size caps from `ai.correspondence.upload.*` (image 512 KB, width ≤2000 via GD re-encode, ≤8 MP), `FileNamer::stored('correspondence', …)`. **File-path rule**: every stored path must start with `correspondence/{id}/` (`safeCorrespondencePath`, `LetterRules::ownsPath`; no `..`, ≤255, no control chars); files live on the `local` (private) disk and are served only through authorised routes or a `temporaryUrl` made after `canView`: 10 minutes for the public link, 1-2 hours for the signed-in viewer (`privateSrc`: the one helper, expiry = start of the hour + 2 h so morphs keep the same URL, no cache). Signature copies are named `signature-…` but are checked only by the folder rule like every other picture. Orphaned files are deleted after commit (`forgetUnused`); `forceDeleted` removes `correspondence/{id}` and the temp dir.

## 11. Smart mode (AI)

`GenerateAction` (lock `ai-correspondence:generate:{uid}`, one fresh generating run per user, quota `HasDailyQuota` feature `correspondence`, `daily_cap` 6, refund only in `markFailed`; `no_refund` = too_large, blocked) → `GenerateCorrespondenceJob(letterId, run)`: `ShouldBeUniqueUntilProcessing` (`letterId:run`), `tries=1`, `failOnTimeout`, `afterCommit()`. **Timeout** = `2 * (timeout 120 + connect 10) + padding 30` = 290 s, clamped to `queue.connections.{default}.retry_after − retry_margin 10`; `uniqueFor = timeout + 30`. `config/queue.php` ships `retry_after` 310 for the redis and database connections, so the full 290 s fits; a lower value would clamp it (180 gives 170 s). `SendCorrespondenceJob` needs only 150 s. ## 12. Delivery to outside people

`DeliverLinkAction` → `SendCorrespondenceJob(letterId, partyIndexes, resend, userId)`: `tries=1`, `timeout=150`, `failOnTimeout`, `afterCommit()`, `failed()` → `stampError('send_failed')`. Per run: ≤5 parties (rest re-dispatched), PDF built once if any chosen mode needs it (`CorrespondencePdf::path`, attach only ≤15 MB else the mail carries a PDF link), **claim** (locked transaction: writes `delivery_error='sending'`+`sending_at`, new random 32-byte token, only its sha256; cap `max_recipients` outside parties), mail sent outside any transaction through `NotifyMail`/`Message(ruleName:'correspondence', template:'styled', attachments)`, **finish** (locked: sets `sent_at`, token hash, `sent` event with the PDF/content hash, or `mail_failed` and rollback of the claim). **Dual-hash resend**: a resend writes `token_hash_next`/`expires_at_next` and keeps the first link alive until the new mail succeeds (failure just drops the `_next` pair); success promotes it and resets `opened_at/open_count`. Keys are static, kebab-case, `correspondence-` prefixed, one per branch root (`correspondence-view-compose|classic|table|report`, `-list-polling|idle`, `-generating`, `-incoming`, `-delivery`, `-mobile-bar`, `-reject-dialog` …); per-id keys only on repeated rows (`correspondence-row-*-{id}`, `-delivery-*-{index}`, `-block-{index}`, `-file-{i}`); multi-root branches and `<x-ui.empty>` get a `<div wire:key class="contents">` wrapper; pollers sit on sibling anchors, never behind an `@if` inside a tag. `paper.blade.php` is the ONE renderer of a letter (letterhead + fields box + body + signature row + cc + page numbers + watermark + inline `@page` A4/A5): the viewer (`mode=screen`), the public link (`link`), the Filament preview and the mPDF job (`pdf`) all include it with data from `CorrespondencePresenter::paperData` — change layout there only. Print contract in `viewPattern.md` §8.39.

## 16. Known accepted limits

JSON columns (`parties`, `recipients`, `tags`, `meta`) are searched with `JSON_CONTAINS`/`INSTR` scans (bounded by status filters and the 6/12-month windows; no generated columns). An outsider's link prefetch (a GET by a mail scanner) counts as an open; HEAD does not. A PDF over the 15 MB attach cap is sent as a link only; over 20 MB PDF generation fails. Resend order across parties is by party index, 5 per run. A wrong, missing or code-less sign-on-behalf attempt returns the same uniform error. `Correspondence::STATUS_WITHDRAWN` is a reserved constant: no code path sets it (withdraw returns the letter to draft), so it is no longer listed in the policy hidden list, `REGISTRY_STATUSES` or the link controller's voided list. There is no draft sweeper: `stale_draft_days` only feeds the admin filter. `evidence_path` (rendered-HTML evidence file) and the per-type `allowed_final_signer_roles` are not implemented (config key only, nothing reads it). Pins and colours are per browser (localStorage).

## 17. How to extend (checklist)

1. New letter type: one `types` entry in `config/ai/correspondence.php` (+ lang label; add `prompt.type_frames.{type}` to make it Smart-capable); nothing else.
2. New transition: add one `*LetterAction` (run via `LetterFlow::run`), authorise on the locked row, call `log()` (lifecycle list if it must survive the 900 cap), add the toast key in `Main::toastKey` and the policy flag in `viewerState`.
3. New party/delivery key: add to `blankParty` only if it must be hashed; delivery state written elsewhere goes through `writeQuiet`.
4. New letterhead option: a key in `Letterhead::defaultConfig/Style` + a field in `LetterheadFormPresenter` + the read in `paperData`/`CorrespondencePdf`; snapshot already carries `config`.
5. New view branch: keyed root, no JS in attributes, factory in `data/correspondence.js` + register it in `modules/correspondence.js` + extend the Vitest file.
6. Anything writing a letter column outside the model hooks must respect §3's frozen guard, §9's sanitiser, and re-run `StateService::flush()` after commit.
7. New file path: under `correspondence/{id}/`, `local` disk, deleted via `forgetUnused`/`forceDeleted`, hashed in `frozenHash` if it is part of the body.
