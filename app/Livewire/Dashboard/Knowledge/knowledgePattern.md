# Knowledge user-panel pattern (shell `Main`, panes `Reports` and `Library`)

## Scope and source of truth

The user-panel slice follows the frozen Knowledge contracts and their §13 reuse mandate. Files are public, protection grade 1; the user panel reads URLs only and does not write attachments. The department catalog is Tier V per contract section 14 (built inside `Media::cachedCatalog`); progress and notes are Tier L and never cached. Shared models, Actions, endpoints and the player remain owned by their respective slices.

## Library and access

`Library` is lazy, uses `FocusOnRecord`, and exposes one computed `library`. Its placeholder has the identical app-shell height and constant `x-data="media()"` expression. A disabled `knowledge:media` view returns 404 before building the library (the route-name guard also covers it). `mount()` writes nothing and runs no «new» query: «new» is derived, never stored. The cached catalog carries the user-independent `owner_id` and `new_until` (`report_date` end of day, else `created_at`, plus `media.new_days`, 30), and `labelled()` turns them into `is_new` per viewer (not the owner, still inside the window, and at least one episode has a file URL); the client hides the chip as soon as the item is played (`played()`). `Media::scopeNewFor` is the badge's version of the same rule (library-visible, not the viewer's own, in the window, something playable, and no progress row on the item or any episode). Changing `media.new_days` needs a `ModelCacheVersion::bump(Media::class)` because `new_until` lives inside the cached value. `SaveProgressAction` refreshes the menu state on a first play only when `StateService::lit()` says the viewer's own dot is lit. The older `seen_by` column and `MarkMediaSeenAction` no longer exist.

## Shell and panes

`Knowledge\Main` is the shell (the Energy shape): `#[Lazy]`, `#[Url(as:'tab')] $activeTab` (default `reports`), `#[Url] $open`; it clamps the tab to `reports` or `media` (media only when `knowledge:media` is on), `switchTab()` whitelists and clears `open`, and mount aborts 404 when `knowledge` is off. Only the active pane is mounted, behind static `wire:key`s; `Reports` and `Library` take `open` as a mount parameter so a stale URL value from the other pane can never focus the wrong record. Switching away from Media, or navigating to another page, pauses playback (video and audio alike) and flushes progress: there is no background player and no on-screen control outside the Library. Old links keep working: `/?tab=reports[&open=]` redirects from `Tabs::mount()` (only when `knowledge` is on) and `/media[?open=&t=]` is an unnamed 302 to `/knowledge?tab=media`. Tenant keys: `knowledge` (everything) and `knowledge:media` (only the Media pane and its endpoints); Reports is never hidden alone. Progress is media-only: the Reports pane never writes progress, `knowledge_progress` has no `report_id`, and the endpoint ignores any item whose type is not `media` (the former report-tracking branch, `media.track_reports` and the «دریافت شده» label were removed 2026-11-21).

`MediaPresenter` reaches roots only through `Media::library($user)`. It eager-loads the ordered, active, unexpired episodes and resolves department and owner names from cached lookups. Episode reads do not apply an independent audience scope: the visible parent grants access. Future episodes remain listed, but every file and track URL is null. Progress and notes are queried only for the current viewer and the listed episode IDs.

Reports attached through `report_ids` are resolved once through `Report::forViewer($user)->notExpired()`. Missing, inaccessible or fileless reports are omitted. Document metadata is built once per distinct report, including when several series attach the same report. Neither raw model serialization nor storage paths enter the payload.

## Browser and player boundary

`media()` composes the player using property descriptors so player getters are not evaluated during object spread. Root getters remain getters as well. Player initialization consumes the root's progress URL and sync configuration before loading the payload. Keyboard binding, Persian time formatting (`faTime`) and native track construction reuse the player's methods; counters use the player's exported `fa` digit helper (`number()` wraps it). The bar and the video overlay are `dir="ltr"` (timeline fills left to right, ArrowLeft = -10s, ArrowRight = +10s; Persian text blocks keep `dir="rtl"`), so `rtl:` flips must not be added inside them; `seekFromEvent` already reads the track's computed direction. `toggleFullscreen()` fullscreens the `[data-video-stage]` element when visible (so the overlay stays), else the shared video element; the `fullscreen` flag follows `fullscreenchange` on the footer. The Library episodes table is the app-wide table (`x-ui.table` + `x-ui.table.tools` with density and `col-toggle`, scope `media`, marker class `media-episode-table`, `data-col` on the optional columns); there is no sort popover because it sorts on the server and lessons are client-side. The table wrapper carries `min-h-[300px]` so the column popover (absolute inside the `overflow-x-auto` wrapper) is not clipped on short tables; a series with no lessons renders only the empty state, no table. New episode fields (`kind`, `ext`, `date_label`) live in the Tier V catalog, so views read them with `??` until the hour-long cache turns over. Track files (`_track` in `mixins/player.js`) are loaded same-origin: when the catalog URL's origin differs from the page's (APP_URL `localhost` vs a `127.0.0.1` or www host) and the path starts with `/storage/`, only the path is used, because the hidden track `<video>` is `crossOrigin='anonymous'` and a cross-origin VTT silently fails with «متن جلسه بارگذاری نشد». The video stage grows to `62dvh` in the maximized view (`[.view-maximized_&]:max-h-[62dvh]`). The pane's own tabs (جلسه‌ها / متن جلسه / یادداشت‌ها / گزارش‌ها) are the app `tab-selector` in a sticky wrapper — the user approved it as is, do not restyle it. The hero actions (play, bookmark, share, declutter, maximize) are separate `h-8` buttons in the Channel header style (`rounded-xl`, `surface-variant`, hover `primary-container`), no grouped bordered container; on phones they stay together at the left end (`max-md:ms-auto`), like desktop. On phones the workspace header is compact (48px cover, one-line title, one wrapping meta line, full-width toolbar row, then a 32px progress ring with the done-count; badges and the long description are `max-md:hidden`); the desktop hero is unchanged. The workspace header's declutter follows Channel/Contact: the whole header collapses (`h-0! py-0! overflow-hidden! pointer-events-none! border-b-0! shadow-none!`) and a solid primary restore button (`unfold_more`) appears at the end of the sticky pane-tabs row while `headerDeclutter` is on; its state is the same `headerDeclutter` as the table tools'. The workspace `<main>` overrides `.custom-scrollbar`'s `scrollbar-gutter: stable` with `[scrollbar-gutter:auto]!` — otherwise the reserved RTL gutter leaves an uncoloured strip beside the hero gradient. The hero header is a flat surface with a bottom hairline on phones and a soft 55% primary-container gradient from `md:` up; phone spacing is tight (no double margins around the video stage, the lessons table's `min-h-[300px]` is `md:` only). The Library header tools follow Channel/Project order: `x-ui.buttons.chat-scale` (shared `chat-ui-scale` key via `chatScaleMixin`; `chat-scale` class only on the sidebar `<aside>` and the shrink-to-fit hero toolbar div — never the whole hero `<header>` (CSS `zoom` on a full-width block overflows its container and shifts the pane), the video stage or the player bar), notification legend, help legend, then a reactive count (`visibleItems.length`); the hero actions run reminder (first, on the right of play; `key-suffix="hero"` keeps its wire:key distinct from the row's), play, bookmark, share, then maximize and declutter like Channel; the search `focus-chip` is included for `$open`. Mute, push, font and pattern pickers and the phone «more» menu were deliberately not ported. Reminders are in (the owner confirmed every records module has them): `Media` uses `HasReminders`, library rows pass `:for="(new Media)->forceFill(['id' => …])"` to `x-ui.row-actions` (never `Media::make()`, which drops the non-fillable id) (hover-reveal inline trigger, no extra query — `Reminder::openForUser()` is memoized per request), and `Reminder::HOST_ROUTES` maps `Media` to the `knowledge` route with `tab=media`. Library rows use the shared `x-ui.row-actions` (pin + palette, `:mute="false"`, `pin-scope="media-pin"`, row needs `x-data="{ tagOpen: false }"`); pin and bookmark are two different things: pin = `media-pin` (`pinned-media`, moves the row to the top via `pinned(item)`), bookmark = `media` (`saved_media`, hero button, row bookmark and the «فقط نشان‌شده‌ها» filter) — never wire both to one scope. The transcript tab renders chapters as a single row of medium cards (`w-36 md:w-40`, faint time above a two-line title, no heading, count or icons) with no scrollbar and previous/next arrow buttons calling `scrollBy` — the user rejected both the big snap-carousel cards and the tiny Channel-style chips and cues as a bounded vertical panel (time pill + text, active cue highlighted). The note textarea reuses the shared `maximize-trigger` / `maximize-overlay` with a local `x-data` whose `value` getter/setter proxies `noteBody` (clamped to 500 characters), because the textarea's own `maximizable` mode is Livewire-entangle only. A pane's `max-widget` z-index is trapped inside the pane's `animate-fade` stacking context, so the shell's `z-10` tab-selector buttons would paint above a maximized pane; the shell selector carries `[.view-maximized_&]:invisible` (hidden, not removed, so no layout shift).

Selection is view-only: browsing another item must not overwrite the currently playing episode. A moment link stores a pending seek without autoplay; the first explicit play supplies it through the player's resume hook. Search uses `highlightMatch` for escaped highlighting and the existing exported `normalize` from `memberPicker.js`; `highlightMatch.js` itself has no normalization helper.

Search keys and original ordering are indexed once per library payload. One parent effect filters and orders sidebar rows rather than recomputing the complete filtered library per row; rows past the first 30 stay in the DOM but hidden (`rank < rowLimit` in `media()`), revealed in steps of 30 by a client-mode `<x-ui.buttons.load-more>` — because `ranks` regenerates from the filtered list, a search naturally lifts hidden matches above the limit. The workspace mounts only the selected item's template, including only one video stage. Notes capture their episode ID before awaiting the request so a late response cannot attach a note to the wrong selection.

Unlock timers use the server clock offset. All locks due together cause one library refresh; no guessed file URL is constructed. Refresh failures have a manual retry. Mutation observers, timers, request controllers and track hosts are cleaned up on destroy.

## Admin entry, permissions and stats (2026-11-21)

The admin panel has ONE sidebar item «دانش سازمانی» for Report, Media and KnowledgeProgress (AiReport joins as a switch button): `ReportResource::knowledgeEntry()` decides which of the three owns the entry for the current admin (tenant `knowledge:media` + each resource's `canViewAny()`), and every list page flips between the tables through `ReportResource::switchActions()`. Permission module keys are `report`, `media`, `knowledge_progress` (via `AuthorizesByPermission`); `lang/fa/resources/knowledge_progress/strings.php` gives the permission matrix its Persian label, and `Permission::availableModules()` (cache key `permission_modules`, one day) must be flushed on deploy. The dashboard `ModuleAnalyticsWidget` has a `media` tab (five stats, hidden by `knowledge:media` and by `MediaResource::canViewAny()`). Since 2026-11-21 the admin side is parity-complete with Report: `MediaResource::infolist()` renders the View modal through `MediaInfolistPresenter` (extends `ReportInfolistPresenter`, label-only overrides + cover/kind/duration; the episodes manager carries its own infolist of the same entries), and every record page has a read-only `ProgressRelationManager` («پیشرفت کاربران») reusing `KnowledgeProgressTablePresenter` columns, mounted only when `progress()->exists()` with the `EventSharesRelationManager` `deniedByPermission()` no-rows override so the hidden-tab clue never lies. `MediaResourceTest` owns the mount gating and the infolist compose assertions.

The Library sidebar has no sort control (removed 2026-11-21 as meaningless for a short list): `visibleItems` orders pinned first, then catalog order (`itemOrder`); do not re-add a `sort` state or dropdown.

The module's page script is a lazy route chunk, not part of the app-wide bundle: `resources/js/components/alpine/modules/knowledge.js` registers `report` and `media` through `registerModuleData`, `main.js` no longer imports or registers either, and the chunk is wired in `ModuleChunkComposer`, `ModuleAssetChunksComposer` and `vite.config.mjs` (`scriptPattern.md` §16). A new Alpine factory used by either pane goes into that chunk, never back into `main.js`.

`Media::playableFor()` (the guard on every progress sync, mark-done and note add) fetches the requested playable lessons first, then checks visibility only for their parent ids with `library($user)->whereIn('media.id', …)`; never embed the whole `library()` subquery inside the candidate query (it ran twice per statement and scaled with the library).

`media.js` keeps its derived data in per-instance closure caches (private to each `media()` call, never on the reactive object) rebuilt only in `readLibrary()`: `byId` (O(1) lookups through `lookup(vm, id)`, which reads `vm.items` first so Alpine still tracks the dependency), `searchIndex`, `hitKeys` (per-series episode search keys), `departmentList`, plus memoized `normalize` keys for the sidebar and transcript queries and a per-accent style cache. Any new derived structure must be cleared and refilled there, and nothing may call `this.items.find()` on the hot path.

## Reused UI

The shell, rail, row grammar and collapse include mirror Channel; route navigation and download behavior mirror `Knowledge/Reports`. Title, route and Alpine tabs, form buttons and fields, semantic table, bookmark, row-actions, saved-empty, quota meter, progress ring, empty states, skeletons, dialogs and maximize backdrop all use the shared components. The cinema view is the standard maximize (`maximize` mixin, maximize button, `max-backdrop`); the media code never writes the focus store. The video stage and the video/audio element follow the current episode (`isVideo`), never the series-level `kind`, which is presentation only. Rich descriptions use `rich-colors`.

No custom player skin, progress SVG, loading spinner, toast shell, normalizer or clipboard implementation is introduced. Since 2026-11-21 the shared `x-ui.decor.progress-ring` takes live Alpine values (`alpinePercent`/`alpineLabel`), so the hero header (56px desktop, 32px phone), the sidebar rows (24px, `x-show` at >0%) and the episode status column (30px) render the shared component directly — no per-view SVG or hand-rolled linear bar remains anywhere in the pane. The episode status cell pairs the ring with `x-ui.decor.status-pill` (one static pill per state behind `x-show`: done=tertiary, current=primary, locked/new=neutral) instead of a ternary text span. The sidebar and transcript searches follow viewPattern §5's client-side visual language (`md3-input` floating label, 20px icon, shared `close-button`); the sidebar adds `pl-20` + `maximize-trigger`/`maximize-overlay` with a local `value` getter/setter proxying `query`. The episodes table head uses the Report-pane thead vocabulary (`surface-container-low` fill, uppercase `text-xs`).

## Verification boundary

The integrated checkout runs the affected PHP and JS test files (one file at a time; several use the live dev database, so assert per-user rows and never absolute counts). Still needing a real browser: the unlock-refresh of the server-rendered download/lock cells inside the workspace `<template x-if>` (Livewire morphs `childNodes`, not a template's `.content`), maximize/dark/phone checks, and seeking, which needs a server that honours HTTP Range (`artisan serve` does not).

## Master tests

**Module video guides (2026-11-22).** `media.module` (nullable string 40, indexed, folded into the 2026-11-21 migration behind a `hasColumn` guard) links a top-level video or series to a module id from `config/modules.php`; admin picks it in the Media form (`MediaFormPresenter::module()`, hidden for audio). `Media::guideMap($departmentCode)` is one Tier V cached query per department axis and day (key `guides:{dept|all}:{date}`; module => id; active, `visibleTo($dept)`, released, not expired, top-level, `playable()` (own file, or a series with an active released episode — the scope shared with `newFor`); `pinned` then `position` then `id` wins among what that department can see) and `Media::guideFor($module, $user)` is a pure array lookup on it, so a header costs two cache reads and zero database queries per render. Admin saves/deletes invalidate it through the global `ModelCacheServiceProvider` version bump. `<x-ui.video-guide>` renders a `play_circle` link to `route('knowledge', ['tab' => 'media', 'open' => id])` (new tab) only when `knowledge:media` is on and a visible guide exists; `<x-ui.title guide="module-id">` places it after the `actions` slot, beside the legend buttons. Modules opt in with one `guide=` attribute on their title; the admin dropdown lists only `MediaFormPresenter::GUIDE_MODULES` (the 24 ids that carry the attribute), so add an id there when a new header opts in.

`tests/Feature/Livewire/Dashboard/MediaTest.php` owns payload, parent audience, expiry, lock URL protection, viewer-owned state and deep-link assertions. ReportModelTest retains the Office-file thumbnail fallback. `data/__tests__/media.test.js` owns pure client filtering, pin ordering, selection, moment links, lock refresh, notes and teardown.

Player correctness is not certified by this slice: its transport, persistence, video host, sync queue and duration rules are owned by the admin/player slice and must pass its own master tests and the integration browser check.
